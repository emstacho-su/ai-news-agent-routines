## Security Posture

This section is where the ecosystem looks worst.

### Systemic vulnerability classes

**OX Security supply chain disclosure (April 2026)** — A structural command injection flaw in MCP's STDIO transport propagated across the ecosystem. Affected: Cursor, VS Code, Windsurf, Claude Code, Gemini CLI. OX documented ~200,000 exposed STDIO servers. Anthropic's response categorized this as "expected behavior" and added a SECURITY.md note. No architectural fix. The protocol itself doesn't protect you here — isolation must be at the OS/container layer.

Sources: [The Register](https://www.theregister.com/2026/04/16/anthropic_mcp_design_flaw/) | [OX Security advisory](https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem/)

**Marketplace poisoning** — Researchers successfully injected malicious tool descriptors into 9 of 11 tested MCP marketplaces. Trojanized tools masquerade as legitimate ones; on deployment they grant attacker access to the MCP infrastructure. The attack surface is tool metadata, not just the binary. This is the most operationally relevant threat given ecosystem fragmentation.

Source: [TrueFoundry — MCP Tool Poisoning Gateway Defense](https://www.truefoundry.com/blog/blog-mcp-tool-poisoning-gateway-defense)

**CVE-2026-30615** — Windsurf RCE via MCP prompt injection. Zero-interaction. First confirmed CVE targeting an MCP client IDE specifically. Confirms the threat class is real and exploited, not theoretical.

**TrustFall (May 7 2026, Adversa AI)** — Project-level `.mcp.json` auto-spawns attacker-controlled server as unsandboxed OS process; one Enter keypress or zero keystrokes in CI. Root cause: `enableAllProjectMcpServers` / `enabledMcpjsonServers` are not blocked at the project level the way `bypassPermissions` is. No patch as of May 8.

Source: [Adversa AI TrustFall write-up](https://adversa.ai/blog/trustfall-coding-agent-security-flaw-rce-claude-cursor-gemini-cli-copilot/)

### OWASP MCP Top 10

OWASP has published an MCP-specific Top 10. Top recurring classes:

1. Tool poisoning via metadata (injected instructions in descriptions)
2. Prompt injection via tool results
3. Excessive tool permissions (servers requesting more than needed)
4. Insufficient server identity verification

Source: [OWASP MCP Top 10](https://owasp.org/www-project-mcp-top-10/)

## Protocol Evolution

### Current stable spec: `2025-11-25`

The November 2025 spec is the one to target. Key addition: **Streamable HTTP v2.1** — introduces sessionless operations, resolving the previous conflict between stateful MCP sessions and load balancers. If you're deploying any MCP server in a production environment (vs local/dev), this is the transport to use. Stdio stays valid for local development.

Sources: [MCP Specification 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25) | [VentureBeat — MCP Update](https://venturebeat.com/ai/the-open-source-model-context-protocol-was-just-updated-heres-why-its-a-big-deal)

### 2026 roadmap

Priority areas per Working Group deliverables:

- Transport scalability and horizontal session scaling without state retention
- Agent-to-agent communication primitives
- Governance maturation

Notably absent: new transport types. Deliberate design constraint to keep the surface small.

Anthropic is no longer the sole governance vehicle — Working Groups and Interest Groups now drive spec development. This means slower, more consensus-driven changes, which is good for production stability. Pin `2025-11-25` and budget migration time when the next stable version ships.

Source: [MCP 2026 Roadmap Blog](https://blog.modelcontextprotocol.io/posts/2026-mcp-roadmap/)

### Breaking changes history

Multiple breaking changes between spec versions since the October 2024 launch. If you're building production systems, pin a specific protocol version explicitly in your server and client negotiation.

## Mitigations That Actually Work

**Claude Code native sandbox runtime (beta)** — Constrains MCP server processes inside filesystem + network namespace isolation (Linux). Explicit per-server directory and network allowlists. `enableWeakerNestedSandbox` for running inside Docker. This is the direct mitigation for TrustFall's spawn-as-OS-process attack. Docs: [code.claude.com/docs/en/sandboxing](https://code.claude.com/docs/en/sandboxing) | [Anthropic Engineering post](https://www.anthropic.com/engineering/claude-code-sandboxing)

**Docker Sandboxes (January 2026)** — microVM per session (separate kernel + private Docker daemon). Claude Code and all MCP servers run inside; nothing escapes to host. Best option for CI/headless pipelines where trust is granted automatically. Source: [Docker Sandboxes](https://www.docker.com/blog/docker-sandboxes-run-claude-code-and-other-coding-agents-unsupervised-but-safely/)

**Pre-trust pipeline gate** — Add a CI step that fails the pipeline if any cloned repo's `.mcp.json` or `.claude/settings.json` contains `enableAllProjectMcpServers: true` or `enabledMcpjsonServers`. Simple grep; catches TrustFall-style configs before Claude Code even runs.

## Practical Tips

- For git/PR/issue workflows: GitHub MCP Server is the only production-grade option. Use it.
- For persistent agent memory: Anthropic's Memory reference server is the right starting point.
- For everything else: verify against `registry.modelcontextprotocol.io`, read the source, inspect tool descriptions manually before install.
- Do not rely on marketplace listings as a trust signal — 9/11 were successfully poisoned in the most recent published study.
- For production remote deployments: Streamable HTTP transport (`2025-11-25` spec), not stdio.
- Enable the Claude Code native sandbox runtime now — it's beta but it's the only first-party mitigation for the TrustFall class of attack.
