## Tools & Frameworks

### [NEW] llm-d 1.0: Kubernetes-Native Distributed LLM Inference for Agent Workloads

Google and partners released llm-d 1.0 on October 20, 2026 — a CNCF sandbox project that adds LLM-aware routing directly to Kubernetes. The practical upgrade over plain vLLM-on-k8s: prefix-cache-aware routing (requests sharing a prompt prefix route to the node that already holds that KV cache), queue-size-aware load balancing, and a unified endpoint over mixed GPU/TPU pools. At the launch demo, Google ran 1,000 concurrent sandboxed agent sessions against a single llm-d endpoint across vLLM, SGLang, and Cloud TPUs without manual sharding. The project integrates with GKE via the Inference Gateway and supports both RL post-training traffic (long rollouts, irregular batches) and standard inference.

Sources: [IT Brief](https://itbrief.com.au/story/google-launches-llm-d-1-0-for-distributed-ai-inference), [letsdatascience](https://letsdatascience.com/news/llm-d-releases-open-distributed-inference-stack-efb1de62), [Google Cloud blog](https://cloud.google.com/blog/products/ai-machine-learning/enhancing-vllm-for-distributed-inference-with-llm-d)

**Why it matters:** If you're running multi-agent pipelines in Kubernetes, llm-d solves the prefix-cache waste problem — today vLLM is naively round-robin, so a 10k-token system prompt gets re-prefilled on every node. llm-d routes sticky. At agent scale this meaningfully drops TTFT and cost. Worth watching the GKE Inference Gateway integration for a managed path.
