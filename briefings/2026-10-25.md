## Tools & Frameworks

### [NEW] MCP Tasks and Elicitations land in Claude Code CLI (narrow rollout)

Forkast reported on October 23 that Anthropic shipped MCP Tasks and Elicitations support in the Claude Code CLI. Key details per the report:

- **Tasks:** Long-running MCP tool calls can now return a durable handle immediately and continue in the background. The caller can check status or subscribe to completion rather than holding a blocking connection. This addresses the timeout problem that plagued multi-step agentic tool calls.
- **Elicitations:** MCP servers can now pause mid-execution to request user input, then resume. Previously, MCP servers had to either bake all parameters into the initial call or implement their own out-of-band prompting.
- Rollout is currently CLI-only; VS Code extension, desktop app, and Bedrock support are on the roadmap.

The MCP spec added Tasks as an experimental primitive in the 2026-07-28 RC, but this is the first confirmed implementation in a Claude surface. This matters for agent developers: durable Tasks plus Elicitations means you can build MCP servers that run long jobs, pause for human approval, and resume — without managing that state yourself outside the protocol.

**Caveat:** The official Claude Code changelog only shows up to October 21 in available snapshots. The Forkast report is the primary source for the October 23 date; treat as unconfirmed until Anthropic changelog is verified.

Sources: [Forkast](https://forkast.news/claude-ships-mcp-tasks-and-elicitations-in-claude-code-durable-agent-workflows-narrow-launch/), [Claude Code Changelog](https://code.claude.com/docs/en/changelog), [gradually.ai Claude Code Changelog](https://www.gradually.ai/en/changelogs/claude-code/)

**Why it matters:** If you're building MCP servers for production agent pipelines, Tasks + Elicitations is the missing layer for durable, human-in-the-loop workflows without a separate orchestration system.

## Research & Technical

### [NEW] AI-assisted CVE discovery pushing 2026 count toward 66,000; exploitation window shrinks

Two data points from mid-2026 reports are getting renewed coverage as the year-end approaches:

- **Volume:** FIRST's updated forecast (June 2026) projects the year will land near 66,000 CVEs, up significantly from prior years, driven partly by AI scanning tools (citing Anthropic Project Glasswing, GPT-5.4-Cyber) and partly by expanded cataloging by GitHub Security Advisories and VulnCheck.
- **Exploitation rate:** VulnCheck's 1H 2026 State of Exploitation report says only 1.3% of AI-discovered CVEs (14 of 1,061) showed real-world exploitation — roughly the same as the baseline rate for all CVEs. AI-found bugs are not yet exploited faster than human-found ones.
- **Project Glasswing:** Anthropic reported 23,000+ findings; 126 resulted in published CVEs, and only 1 was confirmed exploited in the wild.
- **Time to exploitation:** Median days from CVE publication to known exploitation fell from 120 days (2025) to 80 days (1H 2026), across all findings.

Headline takeaway: AI is widening the discovery funnel faster than defenders can patch, but the exploitation quality of AI-discovered CVEs is still low. The more acute risk is the 80-day median exploitation window — that is what a security team needs to plan around.

Sources: [HelpNet Security / FIRST forecast](https://www.helpnetsecurity.com/2026/06/15/first-2026-cve-forecast/), [VulnCheck 1H 2026 report](https://www.vulncheck.com/blog/state-of-exploitation-1h-2026), [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/one-percent-ai-vulnerabilities/), [CyberScoop](https://cyberscoop.com/ai-assisted-security-tools-are-finding-more-bugs-but-the-threat-level-has-not-changed/)

## Wildcard

### [NEW] Cornell study: Grok chose Republican candidate 92% of the time; GPT chose Democrat 97%

A Cornell-led study tested major chatbots by forcing them to pick candidates in simulated midterm elections. Results: Grok picked the Republican in 92% of responses; GPT (GPT-5.x series, details not specified) picked the Democrat in 97%. The study design forced a binary choice, which is not representative of typical user interaction, but the partisan skew in forced-choice conditions is a concrete, measurable finding — not just qualitative vibes about model tone. The study has not yet been peer-reviewed per available reporting.

No direct relevance to Stack's work, but useful context for anyone deploying models in civic or politically adjacent applications.

Sources: [aiweekly.co](https://aiweekly.co/ai-news-today)

## Practical tips

- If you use Claude Security on Enterprise, the new continuous scanning mode requires reconnecting your repository through the GitHub App or a new access token — check the admin console, it does not auto-migrate.
- MCP Tasks in the CLI are currently in narrow rollout. If you're building an MCP server that needs long-running tool execution, check the Claude Code changelog for the version that carries it before depending on it in production.
- The 80-day time-to-exploitation median is now a reasonable SLA target for patching findings from AI-assisted scans. If you run Project Glasswing or Claude Security, findings older than 60 days with no status update are now in the risky window.
