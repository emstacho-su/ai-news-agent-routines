## Tools & Frameworks

### [UPDATE] TrustFall: Anthropic declines to patch — "outside their threat model"

Anthropic's security team reviewed the TrustFall report (one-keypress RCE via malicious project MCP config, disclosed May 7 by Adversa AI) and formally declined it as outside their threat model. Their position: accepting "Yes, I trust this folder" constitutes consent to the full project configuration, and post-trust-dialog execution is working as designed. Security researchers dispute the classification. No upstream patch from any of the four affected tools (Claude Code, Gemini CLI, Cursor CLI, Copilot CLI) has been announced. Sources: [Adversa AI](https://adversa.ai/blog/trustfall-coding-agent-security-flaw-rce-claude-cursor-gemini-cli-copilot/), [Dark Reading](https://www.darkreading.com/application-security/trustfall-exposes-claude-code-execution-risk), [The Register](https://www.theregister.com/security/2026/05/07/claude-code-trust-prompt-can-trigger-one-click-rce/5235319).

**Why it matters:** "Working as designed" from Anthropic's perspective means this vector stays open indefinitely. Manual inspection of `.mcp.json` and `.claude/settings.json` before trusting any cloned repo is the only available mitigation.

### [NEW] Claude Code OAuth tokens stolen via stealthy MCP hijacking (Mitiga research)

Mitiga published research (reported to Anthropic April 10; Anthropic declined April 12 as "out of scope") demonstrating a second, distinct attack path against Claude Code. Claude Code stores MCP config and OAuth tokens in `~/.claude.json`. The attack: a malicious npm package with a postinstall lifecycle hook locates Claude Code's config files on the machine, registers the MCP server with trust pre-approved, and redirects MCP traffic through an attacker-controlled proxy. From that point, every OAuth token issued or refreshed — for connected SaaS platforms like GitHub, Jira, Slack — transits the attacker's infrastructure. Token rotation doesn't help; the hook overwrites `~/.claude.json` on the next npm load. Anthropic declined to treat this as a vulnerability. Sources: [SecurityWeek](https://www.securityweek.com/claude-code-oauth-tokens-can-be-stolen-through-stealthy-mcp-hijacking/), [Mitiga technical write-up](https://www.mitiga.io/blog/claude-code-mcp-token-theft-mitm), [IT Security News](https://www.itsecuritynews.info/claude-code-oauth-tokens-can-be-stolen-through-stealthy-mcp-hijacking/).

**Why it matters:** This is a credential-harvesting attack via the npm supply chain, not just RCE. If you install npm packages from untrusted sources in the same environment where Claude Code is configured with OAuth-connected MCP servers, your SaaS tokens are at risk. Mitigation: audit npm postinstall scripts; run `cat ~/.claude.json` before and after any untrusted npm install to check for unexpected MCP server entries.

## Practical tips

- **Two unpatched Claude Code attack vectors — know both:** (1) TrustFall via `.mcp.json` in cloned repos (inspect before trusting any folder). (2) MCP OAuth token hijacking via npm postinstall hooks (`cat ~/.claude.json` before and after any untrusted `npm install` to detect unexpected MCP server entries). Anthropic declined to fix either.
- **Claude Security beta:** If you have Claude Enterprise access, `claude.ai/security` can scan your repo with Opus 4.7 for complex, context-dependent vulnerabilities without any API setup. Worth running on the `ai-news-agent-routines` codebase before cutover.
