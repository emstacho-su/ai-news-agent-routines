## Tools & Frameworks

### [NEW] CrowdStrike AI Kill Switch: authorized terminate for running agents

CrowdStrike shipped an AI Kill Switch inside Falcon Guardian, announced at Fal.Con Europe (Barcelona, Nov 3, 2026) ([CrowdStrike blog](https://www.crowdstrike.com/en-us/blog/crowdstrike-introduces-ai-kill-switch/)). An authorized administrator can cut off an AI agent's access to the models it depends on by blocking them at the AI gateway, which causes the agent to stop making decisions ([CSO Online](https://www.csoonline.com/article/4244509/crowdstrike-launches-ai-kill-switch-to-shut-down-rogue-agents.html)). Every kill-switch activation is recorded in a full audit trail. Endpoint-level process termination and network isolation are listed as coming soon. SOAR automation for no-code kill-switch workflows is in the roadmap via Charlotte Agentic SOAR.

**Why it matters:** The first production kill-switch from a major security vendor is an explicit acknowledgment that agentic workloads need circuit breakers, not just detection. If you're deploying Claude Code agents or any MCP-wired automation in a corporate environment, understanding how this fits your incident-response runbook is now a real question.

### [UPDATE] Gemini 4 Carbon API: open to paying developers, $2/$10/M intro pricing

**Background:** Carbon was announced Oct 28 as a security-focused model with cybersecurity skills, initially limited to select cyber defenders through a Fairwind pilot program.

**New:** As of approximately November 10, Google opened Carbon to paying developers via Google AI Studio and enterprise APIs ([Technobezz](https://www.technobezz.com/news/google-gemini-4-carbon-opens-developers), [braindetox.kr](https://braindetox.kr/en/posts/gemini_4_carbon_general_availability.html)). The model ID is `gemini-4-carbon`. Note: some trackers still list no public API as of Nov 5, so verify against Google AI Studio's current model list before building against it.

## Model Releases

### [NEW] Inkling 2 Small open weights: 594B MoE, 17B active, Apache 2.0 (pending confirmation)

Thinking Machines Lab (founded by Mira Murati) launched Inkling 2 Small on November 5 as a 594-billion-parameter mixture-of-experts model with 17B active parameters, available initially on its Tinker platform with closed weights ([letsdatascience.com](https://letsdatascience.com/news/thinking-machines-lab-releases-inkling-2-small-a-594b-moe-mo-2b2a96ce)). The lab said it would release weights under Apache 2.0 approximately one week after launch, pending safety evaluations and partner red-teaming ([runtimewire.com](https://runtimewire.com/article/thinking-machines-inkling-2-small-open-weights)). That window closes this week. As of this writing, open-weight availability is still being confirmed—check Thinking Machines' announcements or Hugging Face directly.

**Why it matters:** Apache 2.0 at 594B MoE is aggressively open—commercial fine-tuning with no royalties. 17B active params at inference means cost comparable to a mid-tier dense model. Worth watching against Qwen3-8-Max and Kimi K3 open releases.

## Business & Wildcard

### [NEW] OpenAI ChatGPT Wallet: agent-payment authorization layer

OpenAI is launching ChatGPT Wallet, initially for US ChatGPT Pro subscribers ([Sam on AI](https://samonai.substack.com/p/ai-brief-november-14-2026)). The mechanic adds an explicit approval gate: an agent can prepare a transaction (purchase, transfer), but cannot execute it without human authorization. Structurally similar to a "confirm before commit" pattern. No announced timeline for broader rollout or developer API access.

**Why it matters:** This is the first production payment authorization layer from a major model provider. The human-in-the-loop design is explicitly framed as addressing the concern that autonomous agents might execute purchases without user intent. Relevant architectural precedent if you're building agents that touch commerce.
