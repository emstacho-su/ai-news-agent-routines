### [NEW] Enterprise-Managed MCP Authorization: zero-touch OAuth for Claude Enterprise (Okta launch)

Anthropic announced Enterprise-Managed Authorization for MCP connectors, launched June 18. Admins provision MCP connectors once via their IdP (Okta is the first supported provider) and employees inherit access automatically on first Claude login — no individual OAuth dance, no per-user re-authorization. Access is scoped to existing IdP groups and roles, so onboarding a new hire automatically carries the right connector permissions. Seven MCP providers support the standard at launch: Asana, Atlassian, Figma, and Supabase are confirmed; Slack is listed as coming soon. Ramp reports 2,000 employees provisioned through Okta with zero additional steps. The extension is now stable and works across Claude chat, Claude Code, and Cowork (Team and Enterprise plans only).

Sources: [Okta newsroom](https://www.okta.com/en-ca/newsroom/press-releases/okta-becomes-a-featured-identity-provider-powering-secure-ai-agent-connections-for-claude-enterprise/), [MCP blog](https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/), [AI Weekly](https://aiweekly.co/alerts/anthropic-introduces-admin-managed-mcp-auth-for-claude-enterprise)

**Why it matters:** This closes the enterprise MCP deployment gap — previously, every user had to individually authorize each connector, which was a blocker for large-scale rollouts. Scoping to IdP groups means revocation is also automatic (deprovisioned employee loses connector access immediately). Relevant if you're building team-facing Claude Code integrations at scale.

## Tools & Frameworks

### [UPDATE] Claude Code v2.1.181 + v2.1.183: `/config` in-prompt, file-corruption fixes, auto mode safety

**v2.1.181 (June 17–18):**
- `/config key=value` syntax lets you change arbitrary settings from the prompt mid-session (no need to exit and edit settings.json manually).
- Fixed: Write/Edit generated zero-byte or truncated files on network drives and cloud-sync folders (this was a silent data-loss bug).
- Fixed: Idle sessions lost their history when another process cleaned the transcript; sessions now survive concurrent cleanup.

**v2.1.183 (June 19, today):**
- Auto mode now blocks destructive git commands (e.g., `git reset --hard`, `git checkout -- .`, `git clean -f`) when the user did not explicitly ask to discard local work. The safety classifier pre-screens subagent actions before launch for this class of irreversible operation.

Sources: [DevelopersIO](https://dev.classmethod.jp/en/articles/20260618-cc-updates-v2-1-181/), [Claude Code changelog](https://code.claude.com/docs/en/changelog), [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

**Why it matters:** The file-corruption fix on network drives matters for anyone running Claude Code over a mounted share or Dropbox/OneDrive folder. The v2.1.183 git safety guard directly addresses a category of "Claude helpfully deleted my uncommitted work" incidents.
