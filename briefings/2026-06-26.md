### [UPDATE] Claude Code v2.1.191: /rewind, 37% CPU Savings, Reliable Agent Stop

**Background:** Claude Code has been on a weekly release cadence since June; v2.1.185 (June 20) added terraform/pulumi/CDK destroy guards in auto mode.

**New:** v2.1.191 (released June 25) adds `/rewind` to undo a `/clear` and restore the conversation to where it was before. CPU usage during streaming responses drops ~37% via coalesced update batching. Memory growth in long sessions is now suppressed (terminal output cache was the culprit). Background agents that were stopped no longer resurface — stopping from the tasks panel is now permanent. Also fixed: `Cmd+click` on links in Ghostty over ssh/tmux fullscreen, `/voice` showing policy-violation reason instead of generic "not available," and scroll-position jump-to-bottom during streaming reads. Sources: [DevelopersIO](https://dev.classmethod.jp/en/articles/20260625-cc-updates-v2-1-191/), [Claude Code changelog](https://code.claude.com/docs/en/changelog).

**Why it matters:** `/rewind` directly addresses the common pattern of accidentally clearing context mid-session. The CPU and memory savings matter for long agentic runs — 37% lower CPU could meaningfully reduce throttling on resource-constrained hosts.

## Tools & Frameworks

### [NEW] OpenAI + Broadcom Jalapeño: First Custom AI Inference Chip

OpenAI and Broadcom unveiled Jalapeño, OpenAI's first custom-built Intelligence Processor — a reticle-sized ASIC designed end-to-end for LLM inference. Built in a nine-month development cycle (claimed fastest ASIC cycle ever for high-performance semiconductors), the chip was co-designed using OpenAI's own models. Early benchmarks show ~50% cost reduction per inference vs. current GPU alternatives. Engineering samples were delivered June 24; initial production deployment is targeted by end of 2026, with gigawatt-scale datacenter builds alongside Microsoft planned for 2026 onward. Sources: [OpenAI announcement](https://openai.com/index/openai-broadcom-jalapeno-inference-chip/), [TechCrunch](https://techcrunch.com/2026/06/24/openai-unveils-its-first-custom-chip-built-by-broadcom/), [Tom's Hardware](https://www.tomshardware.com/tech-industry/artificial-intelligence/broadcom-and-openai-unveil-custom-built-jalapeno-inference-processor-openais-first-chip-is-a-massive-reticle-sized-asic-built-in-an-ultra-fast-nine-month-development-cycle).

**Why it matters:** The move away from GPU dependency is strategically significant. A 50%-cheaper inference path — if the benchmarks hold — reshapes OpenAI's cost structure and pricing leverage against Anthropic. The 9-month dev cycle is also a direct rebuke to the assumption that custom silicon requires 2-3 year cycles.

### [UPDATE] MCP 2026-07-28 Release Candidate Live: Protocol Goes Stateless

**Background:** The MCP 2026 roadmap has been targeting a stateless Streamable HTTP transport and a Tasks lifecycle API.

**New:** The release candidate is available today, with final spec shipping July 28 after a 10-week validation window. Headline change: MCP is now stateless at the protocol layer. The `Mcp-Session-Id` header and all session-level state are removed; `initialize`/`initialized` handshake is gone. Protocol version, client info, and capabilities now travel in `_meta` on every request. A `server/discover` method replaces the startup handshake for capability negotiation. Practical consequence: remote MCP servers can now run behind plain round-robin load balancers with no sticky routing, shared session stores, or gateway-level DPI. Three features are deprecated (with replacements), none removed — minimum 12-month lifecycle per new deprecation policy. Server-initiated requests are now constrained to only fire while a client request is actively being processed (no more ambient elicitations). Sources: [MCP blog RC announcement](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), [Microsoft Community Hub](https://techcommunity.microsoft.com/blog/appsonazureblog/mcp-just-went-stateless-%E2%80%94-what-the-2026-spec-changes-about-scaling-on-app-servic/4530222).

**Why it matters:** If you're building or hosting MCP servers, this is the spec to migrate to. Stateless = you can deploy the server behind any CDN or standard load balancer. The constraint on server-initiated requests also closes a surface where ambient agent prompts could fire out-of-band — meaningful for anything security-adjacent.
