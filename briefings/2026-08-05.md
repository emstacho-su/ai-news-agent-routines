### [UPDATE] Claude Code v2.1.222: worktree isolation bypass patched

**Background:** Claude Code has shipped rapid changelogs through July–August 2026; yesterday's briefing covered v2.1.221.

**New (v2.1.222, released August 4):**
- **Worktree isolation bypass fixed** — worktree-isolated sessions and their subagents could previously run destructive git commands (e.g., `git reset --hard`, `git clean -f`) against the main checkout; isolation now applies to file edits and Bash in every session type.
- **PreToolUse hook bypass fixed** — auto-allow hooks were bypassing tool restrictions in background agent tasks (summaries, compaction, session renames).
- `/usage-credits` fix for Team/Enterprise members whose earlier request was dismissed (was showing "already sent a request" incorrectly).
- Startup connectivity check hanging behind an HTTPS proxy fixed.
- "Connection closed mid-response" false errors on completed responses fixed.

Sources: [Claude Code Changelog (August 2026)](https://www.gradually.ai/en/changelogs/claude-code/), [Claude Code Changelog — Releasebot](https://releasebot.io/updates/anthropic/claude-code)

**Why it matters:** The worktree isolation bypass was a real security gap for ultracode workflows — subagents in isolated worktrees should not be able to clobber the main tree. Upgrade to v2.1.222 if you're running parallel worktree agents with git write access.

Anaconda announced on August 4 the acquisition of Enkrypt AI, an AI security and compliance company, for an undisclosed sum. This follows Anaconda's July 2026 acquisition of Kilo Code (open-source coding agent). With Enkrypt, Anaconda Platform now spans from dev environment to production: package management (Anaconda), agentic coding (Kilo Code), and runtime AI security (Enkrypt).

Sources: [Anaconda blog](https://www.anaconda.com/blog/anaconda-acquires-enkrypt-ai), [HPCwire AIwire](https://www.hpcwire.com/aiwire/2026/08/04/anaconda-acquires-enkrypt-ai-to-secure-the-trillion-token-enterprise/)

## Wildcard

### [NEW] Ninth Circuit vacates Amazon's CFAA injunction against Perplexity's Comet

The U.S. Court of Appeals for the Ninth Circuit on August 4 vacated the preliminary injunction that had barred Perplexity's Comet browser agent from shopping on Amazon.com. Core holding: it is users, not Perplexity, who "access" Amazon's computers under the Computer Fraud and Abuse Act (CFAA). The panel applied the rule of lenity to resolve CFAA ambiguity against liability and explicitly noted that "little to no existing caselaw directly deals with how to ascribe responsibility for AI agents" under the statute.

The case returns to district court. Amazon's trademark and state-law claims survive. The Ninth Circuit described its holding as narrow and acknowledged the law "will doubtless change." This is the first federal appellate ruling on CFAA liability for AI agent behavior.

Sources: [TFTC](https://www.tftc.io/ninth-circuit-cfaa-amazon-perplexity-comet-browser-ruling), [Bloomberg Law](https://news.bloomberglaw.com/us-law-week/perplexity-overturns-amazon-ban-on-ai-shopping-bot-on-appeal), [Courthouse News Service](https://www.courthousenews.com/ninth-circuit-lifts-block-on-ai-powered-shopping-assistant/)

**Why it matters:** First federal appellate precedent establishing that an AI agent's actions are legally the user's actions (not the developer's) under the CFAA. Has downstream implications for anyone building agentic tools that interact with third-party web services without explicit authorization.

### [NEW] Rust maintainers adopt LLM contribution policy — code, docs, and PR bodies banned

On August 5, five teams within the rust-lang/rust project formally adopted a policy governing LLM use in contributions to the monorepo. Key distinctions:

**Permitted (private use):** asking LLMs questions, analyzing code privately, summarizing for personal notes, private code review.

**Banned from public content:** LLM-generated comments, PR/issue bodies from personal GitHub accounts; documentation including doc comments, safety comments, multi-paragraph source comments, and compiler diagnostic messages.

**Permitted with disclosure:** machine translation, trivial code/prose changes, bug discovery verified by the contributor.

The policy is live in the `rust-lang/rust-forge` repo (PR #1040). Notably this applies only to the five adopting teams; there is no project-wide consensus on AI use.

Sources: [Inside Rust Blog](https://blog.rust-lang.org/inside-rust/2026/08/05/rust-langrust-is-adopting-an-llm-policy/), [socket.dev](https://socket.dev/blog/rust-moves-to-restrict-llm-use-in-contributions), [Linuxiac](https://linuxiac.com/rust-may-limit-ai-generated-work-in-its-core-repository/)

**Why it matters:** Rust is one of the highest-quality OSS projects. Their permitted/banned split is instructive for any team drafting contribution guidelines on AI use — particularly the distinction between private assistance and public artifact generation.
