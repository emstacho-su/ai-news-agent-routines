## Anthropic

### [UPDATE] Fable 5 and Mythos 5 taken offline by US Commerce Department

**Background:** Fable 5 and Mythos 5 launched June 9 — Fable 5 hit #1 on FrontierCode with 95.0% SWE-bench Verified. Three days later, Pliny the Liberator published a jailbreak on X (June 10).

**New:** On June 12, Commerce Secretary Howard Lutnick signed an export control directive ordering Anthropic to suspend access for any foreign national — whether inside or outside the US, including foreign-national Anthropic employees. Unable to verify nationalities in real-time at the API layer, Anthropic blocked all public global access. Enterprise customers and individual users worldwide are now automatically routed to Opus 4.8, with no opt-out. Anthropic's official statement disputes the severity: "the government has only given us verbal evidence of a potential narrow, non-universal jailbreak, which essentially consists of asking the model to read a specific codebase and fix any software flaws" and argues this provides "no Mythos-specific uplift." No restore timeline given as of June 13.

Sources: [Anthropic Statement](https://www.anthropic.com/news/fable-mythos-access), [CNBC](https://www.cnbc.com/2026/06/12/anthropic-disables-access-to-fable-5-and-mythos-5-to-comply-with-government-directive.html), [Bloomberg](https://www.bloomberg.com/news/articles/2026-06-13/anthropic-says-us-limits-foreign-access-to-fable-5-mythos-5), [The New Stack](https://thenewstack.io/us-gov-orders-anthropic-to-pull-fable-5-and-mythos-5-three-days-after-launch/), [VentureBeat](https://venturebeat.com/technology/anthropic-blocks-all-public-access-to-claude-fable-5-mythos-5-following-us-government-order-what-enterprises-should-do)

**Why it matters:** If you're building on Fable 5 — including inside this project (Claude Code Routines) — you need a working fallback to Opus 4.8 now. The bigger signal: cloud-only frontier model access carries hard regulatory risk. A single export control directive can instantly void your SLA with zero recovery timeline. Design for model fallback from the start.

## Tools & Frameworks

### [UPDATE] Claude Code v2.1.176 (June 12)

**Background:** v2.1.172 (June 10) added recursive 5-level deep sub-agent spawning.

**New:** v2.1.176 delivers two new features and several targeted bug fixes.

New features: Session titles now generate in the language of the conversation (set `language` setting to force a specific language). New `footerLinksRegexes` setting adds regex-matched link badges to the Claude Code footer row, configurable via user or managed settings. Bedrock credential caching now honors the IAM credential `Expiration` field instead of a fixed 1-hour TTL — useful if your credentials expire in less than an hour.

Bug fixes worth knowing about: `availableModels` allowlist now blocks alias-model redirects via `ANTHROPIC_DEFAULT_*_MODEL` env vars, and `/fast` refuses to toggle to a model outside the allowlist. Auto mode with Fable 5 no longer hard-fails for orgs that don't have Opus 4.8 enabled — it now routes to best available Opus. Hook `if` conditions for `Read/Edit/Write` tool path patterns (e.g., `Edit(src/**)`, `Read(~/.ssh/**)`, `Read(.env)`) now match correctly — if you have tool-use security hooks, this fix restores expected filtering. Also fixed: file descriptor exhaustion in skill directories; Skill tool permission error in headless mode (regression from v2.1.141); JetBrains 2026.1+ terminal flickering.

Sources: [Official Changelog](https://code.claude.com/docs/en/changelog), [GitHub Releases](https://github.com/anthropics/claude-code/releases), [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

**Why it matters:** The hook `if`-condition fix is the highest-impact for security-conscious setups — path patterns in tool-use rules now filter as documented.
