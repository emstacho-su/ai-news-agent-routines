## Tools & Frameworks

### [UPDATE] Claude Code v2.1.305–307: `allowedMcpServers` change, safety_event hook, HTTP double-send fix

**Background:** v2.1.302 introduced client-side auto-mode model selection and MCP reliability fixes; the series has been on a rapid patch cadence through October.

**New:**
- **v2.1.305–306:** `allowedMcpServers` behavior narrowed — the field now gates which servers the model may call, not just which servers connect. Review your configs if you use allowlists with overlapping server names.
- **v2.1.307:** Adds a `safety_event` hook type for PreToolUse/PostToolUse pipelines, letting hooks emit structured safety signals back to the orchestrator. Also exposes a `/claude-api` api-version endpoint for introspection. Fixes a bug where HTTP-transport MCP tool calls were sent twice — breaking for any write-type tool.

The double-send fix is the highest-priority item for anyone running HTTP-mode MCP servers with side-effecting tools (file writes, database mutations, API POSTs). Sources: [dev.classmethod.jp v2.1.307](https://dev.classmethod.jp/en/articles/20261022-cc-updates-v2-1-307/), [dev.classmethod.jp v2.1.306](https://dev.classmethod.jp/en/articles/20261021-cc-updates-v2-1-306/), [easyspawn.com October summary](https://easyspawn.com/blog/claude-code-october-2026-updates).

## Hardware & Infrastructure

### [NEW] Nvidia DSX POD: Vera Rubin AI factories in a box, 6 months → 14 days deployment

Announced at GTC Berlin (Oct 21), DSX POD is a reference design for complete Vera Rubin NVL72-scale AI factories shipped as pre-integrated, pre-validated modular containers. Partners (Bull, Dell Technologies, HPE, Lenovo, Schneider Electric, Vertiv) build and validate the racks before delivery; the customer receives a ready-to-plug unit rather than a data-center construction project. NVIDIA claims this collapses on-site deployment time from roughly six months to 14 days (assuming site utilities — power, cooling — are already in place). Vera Rubin is described as in full production.

Additional announcements from the keynote:
- **Google Cloud A5X launch:** Google Cloud confirmed A5X bare-metal instances (NVL72-based) will go live "next month" (November 2026), with plans to reach up to 960,000 Rubin GPUs across multi-site clusters. A5X was pre-announced at Google Cloud Next in April.
- **OpenShell:** A reference security architecture for agentic AI workloads. BlueField-4 DPUs handle enforcement; the stack combines Vera Rubin (inference), Vera CPUs (agent ops), and BF4 (security boundary). Targeted at enterprises running large multi-agent pipelines.
- **Efficiency claims (vendor figures):** Up to 100% reduction in cooling water use; same AI output at up to 30% less power vs. prior generation.
- Partner deliveries target early 2027.

Sources: [NVIDIA newsroom](https://nvidianews.nvidia.com/news/nvidia-introduces-dsx-pod-ai-factories-to-accelerate-europes-infrastructure-deployment), [NVIDIA GTC Berlin keynote blog](https://blogs.nvidia.com/blog/gtc-berlin-2026-keynote/), [Analytics India Magazine](https://analyticsindiamag.com/deep-tech/from-humanoid-robots-to-telecom-trials-12-major-announcements-at-nvidia-gtc-berlin-2026), [WebProNews](https://www.webpronews.com/nvidia-dsx-pod-vera-rubin-ai-factory-containers-gtc-berlin), [NVIDIA/Google Cloud blog](https://blogs.nvidia.com/blog/google-cloud-agentic-physical-ai-factories/).

**Why it matters:** If the 14-day deployment claim holds, it meaningfully lowers the barrier for enterprises and sovereign AI programs in EMEA to stand up frontier-scale inference capacity — relevant context for any infrastructure or cloud-cost analysis Stack runs.

## Practical tips

- **HTTP MCP servers with write tools:** Update to Claude Code ≥ v2.1.307 immediately. The double-send bug means every HTTP POST/PUT/DELETE MCP tool was firing twice per invocation — potential data corruption or duplicate records.
- **`allowedMcpServers` audit:** After v2.1.305, double-check your `.claude/settings.json` allowlists. The scope semantics changed; a rule that previously allowed `serverA` won't implicitly cover `serverA-staging` anymore, even if names overlapped in practice.
