## Anthropic

### [UPDATE] Claude Code v2.1.248/251 — restricted mode, cross-session on all cloud platforms, async startup

**Background:** Claude Code has been shipping weekly feature batches since August; the last tracked batch (v2.1.245) landed August 25 with modelPicker, dual cache TTLs, and the glibc 2.44 startup-crash fix.

**New:**
- **Restricted mode** (`--restricted` / `CLAUDE_CODE_RESTRICTED=1`, v2.1.248, Aug 28): removes built-in tools that run commands or code, drops WebFetch unless the tool is explicitly whitelisted, confines file tools to the working directory, and ignores user/project settings files entirely. Designed for CI pipelines and untrusted-input environments.
- **Cross-session messaging** (v2.1.248–v2.1.251): `SendMessage` / `ListAgents` — previously macOS/Linux local only — now work across Bedrock, Vertex, Foundry, and telemetry-disabled setups.
- **Async init**: sandbox and MCP servers now initialize in the background. You can start composing a prompt while they come up. Subcommands that don't need the full agent runtime short-circuit the heavier init path entirely.

**Why it matters:** Restricted mode is a principled hardening surface for running Claude Code in automated pipelines or agent-review workflows where tool exposure needs to be controlled. Cross-session messaging on Bedrock/Vertex is the missing piece for multi-agent coordination in enterprise VPC deployments.

## Tools & Frameworks

### [NEW] Microsoft Agent Lightning v1.0 — RL for any agent, zero production code changes

Microsoft Research open-sourced Agent Lightning v1.0 on August 17. The core contribution is **Training-Agent Disaggregation (TA-D)**: the RL training loop runs in a separate process from the inference path, so an agent can be reinforcement-learned against the exact same harness it runs in production — no separate training scaffold, no environment mismatches. Supports RL, prompt optimization, and supervised fine-tuning. Validated on SWE-bench Verified: Agent Lightning improved Qwen3.5-9B from 41.8% to 56.4% (+14.6pp absolute) using 6K training examples on modest compute. The arXiv paper (2508.03680) accompanies the release.

**Why it matters:** The mismatch between "agent trains in the lab" and "agent runs in prod" has been one of the structural blockers for production agentic RL. TA-D is a clean architecture answer — separating training state from agent state in a way that also maps well onto managed-execution models like Routines. Worth reading before the pattern gets absorbed into orchestration frameworks over the next quarter.

Sources: [The New Stack](https://thenewstack.io/microsoft-agent-lightning-harness/), [Microsoft Research blog](https://www.microsoft.com/en-us/research/blog/agent-lightning-adding-reinforcement-learning-to-ai-agents-without-code-rewrites/), [arXiv 2508.03680](https://arxiv.org/pdf/2508.03680), [CryptoBriefing](https://cryptobriefing.com/microsoft-agent-lightning-agentic-rl/)

## Practical Tips

- **Restricted mode in CI:** `--restricted` is documented as removing all command/code execution tools and ignoring user settings — it's not just a soft flag, it's a hard surface reduction. If you're running Claude Code inside a Routine or a review pipeline, read what's removed before relying on it; the flag was designed for exactly that use case.
- **Agent Lightning architecture:** The TA-D paper is compact and the GitHub repo is out now. Even if you're not doing RL today, the training-inference separation pattern is the right frame for thinking about how Routines-style managed execution could eventually support in-context agent improvement.
