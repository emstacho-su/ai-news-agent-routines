## Anthropic

### [NEW] Claude can now send Gmail and manage Drive files (all paid plans)

Announced August 18; covered by most outlets August 23. Claude's existing Google Workspace connectors graduated from passive read-only to active write actions.

**Gmail — what's new:** Claude can now send new emails, reply to emails, and forward emails. Previous behavior was draft-for-approval; now Claude can take the full send action. Per-send approval is on by default; users can disable it, and Team/Enterprise owners can enforce approval policy org-wide. Anthropic does not train models on Workspace connector data, and Claude inherits the user's existing Google permissions.

**Google Drive — what's new:** Active file management: share files, move files, trash files. Previously read/summarize only. Same approval-before-action default as Gmail.

**Cowork mobile:** Cowork is now available on mobile and web across all paid plans, not just the Claude desktop app.

**Why it matters:** This is the last major blocker for using Claude as a genuine email agent — drafting was already there, delivery was the gap. For a Claude Code session managing a project, being able to send status emails or move Drive artifacts without context-switching is now wired. The send-without-approval option is the one to think carefully about before enabling.

## Tools & Frameworks

### [UPDATE] Claude Code v2.1.233: TaskCreate deprecated, build memory cap, GitLab MR worktrees (Aug 14 — catching up)

**Background:** v2.1.236-237 (Aug 19-20) shipped model env var, idle notifications, and Concise output style.

**New in v2.1.233 (Aug 14) — missed in prior runs:**

- **`TaskCreate`/`TaskGet`/`TaskUpdate`/`TaskList`/`TodoWrite` deprecated** on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer. These tools are removed by default on those models. Restore with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. (Older models unaffected.)
- **`CLAUDE_CODE_TOOL_MEMORY_LIMIT`**: new env var, opt-in Linux memory cgroup for Bash tool processes. Caps the memory a runaway build command can consume before the session stalls. Set in bytes or with `K`/`M`/`G` suffixes.
- **GitLab MR support in `--worktree`**: pointing `--worktree` at a GitLab MR URL opens a session on that branch, matching GitHub PR behavior. MRs display as `!N` in `claude agents` view. Nested subgroup GitLab URLs parsed correctly.
- **GitLab token redaction**: full coverage for all GitLab token families (`glrt-`, `gloas-`, `glptt-`, `glagent-`, `glimt-`, `glsoat-`, `glcbt-`, `glft-`, `glffct-` masked; `glpat-` and `gldt-` fully redacted).
- **`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`**: configures WebFetch session URL cache TTL (default 15 min).

**Why it matters for the v1-routines build:** The `TaskCreate` deprecation breaks any routine or agent that calls those tools without the env var override. If you have workflow scripts using `TaskCreate` in subagents that target Sonnet 5 / Fable 5 / Mythos 5, they will silently fail or error unless you set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` or migrate to the Bash `todos` approach.

## Model Releases

### [NEW] GLM-5.3 (Z.ai): emergent exploit-chain capability, 1,097 CVEs, weights delayed to Aug 28

Launched August 14. GLM-5.3 is a coding-focused post-training update over GLM-5.2, and Z.ai did not intend its primary story to be about security. The capability emerged during training.

**What emerged:** During post-training GLM-5.3 "began reasoning through multiple exploitation stages, forming coherent plans for complete exploit chains" — Z.ai's words, not a researcher's description. The company launched a public Security Disclosure Ledger (cvd.z.ai) documenting the results.

**Numbers:**
- 2,436 total vulnerabilities found across 269 open-source projects (cumulative across GLM-5.2/5.3 post-training)
- 1,097 rated critical or high severity
- 53 CVEs formally assigned at launch; 2,383 under coordinated disclosure embargo as of August 14
- Oldest identified bug reportedly traces to 1981 (Linux/FreeBSD-era code)

**Affected software:** Linux kernel (use-after-free), Apple WebKit (Safari, memory-handling flaw), FreeBSD (parameter-validation bug), GStreamer, Suricata, Joomla, Cursor (the AI code editor) — Cursor vulnerability reported separately by VentureBeat.

**Weights delay:** Z.ai committed to releasing weights ~2 weeks post-launch (targeting ~August 28) for "safety evaluation and hardening." This is reportedly the first Chinese AI lab to cite emergent offensive capability as the explicit reason for a weights hold — a framing more commonly seen from US labs (Anthropic Glasswing, OpenAI Astra Preparedness Framework trigger).

**Caveats:** All numbers come from Z.ai's own ledger. Independent journalists spot-checked the ledger against upstream CVE records and found matching entries for named software. Security researchers have noted the "2,436 bugs" aggregate conflates team, model, dedup, and severity histories into a product-launch number.

[RUMOR] The model also topped CyberGym benchmark "near Mythos 5 level" — no audited leaderboard submission confirmed.

Sources: [TechTimes — GLM-5.3 exploit chains](https://www.techtimes.com/articles/324426/20260814/glm-53-post-training-produced-exploit-chains-zai-never-planned-finds-1097-critical-bugs.htm), [MLQ.ai — weights delay](https://mlq.ai/news/zai-delays-glm-53-weights-after-cybersecurity-tests-show-strong-exploit-capability/), [VentureBeat — Cursor vulnerability](https://venturebeat.com/technology/glm-5-3-is-here-with-advanced-cyber-capabilities-and-reportedly-already-found-a-serious-vulnerability-in-cursor/), [Unite.AI — full launch writeup](https://www.unite.ai/z-ai-launches-glm-5-3-with-frontier-coding-and-a-cyber-capability-that-outgrew-its-training/)

## Practical Tips

**Claude Code: check your workflow agents for `TaskCreate` use.** Any subagent calling `TaskCreate`, `TaskGet`, `TaskUpdate`, `TaskList`, or `TodoWrite` on Sonnet 5, Fable 5, Mythos 5, or Opus 4.8 will fail silently or error as of v2.1.233+. Run `grep -r "TaskCreate\|TodoWrite\|TaskUpdate\|TaskGet\|TaskList" .claude/ routines/` to find exposure. Restore with `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` env var or migrate to direct Bash task tracking.

**Build-command memory leak protection:** Set `CLAUDE_CODE_TOOL_MEMORY_LIMIT=2G` (or appropriate value) in your Claude Code environment to cap runaway `npm run build` / `cargo build` memory growth in long sessions.
