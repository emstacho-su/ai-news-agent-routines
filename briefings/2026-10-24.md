## Tools & Frameworks

### [NEW] 1Password for Agents: multi-agent credential autofill without exposing passwords

1Password launched **1Password for Agents** on October 22, expanding its earlier Claude-only browser-login beta (July 2026) into a full multi-agent product. Launch partners: Meta Muse, OpenAI ChatGPT Work + Dots, SpaceXSI Grok Bot, Town's Townie. Claude Duet integration was announced as "coming soon."

**How it works:** When an agent reaches a login page, it presents a unique digital key to identify itself to 1Password. The user receives an alert and approves on their device. 1Password fills the credentials directly into the browser form — the agent receives only a success/failure status and never sees the password, OTP, or passkey. Scope is strictly per-session and per-item; approving one credential doesn't grant vault-wide access. Opt-in only: agents cannot reach your vault unless you connect an agent connector.

**Caveats noted by security researchers:** An authenticated session can still let an agent view sensitive data or take actions beyond the intended scope — the credential barrier is cleared, but session-level authorization is still the app's responsibility.

Sources: [TechCrunch](https://techcrunch.com/2026/10/22/1password-launches-a-way-for-ai-agents-to-log-in-on-your-behalf-without-seeing-your-password/), [1Password blog](https://1password.com/blog/1password-for-ai-agents), [The Next Web](https://thenextweb.com/news/1password-for-agents-ai-agent-logins), [eSecurityPlanet](https://www.esecurityplanet.com/artificial-intelligence/news-1password-ai-agent-login-password-security/)

**Why it matters:** The credential handoff is the messiest trust boundary in agent pipelines today — most designs currently either (a) pass plaintext credentials to the agent, (b) rely on browser-session cookies the agent inherited, or (c) don't handle logins at all. 1Password's model — agent identity key + user in-the-loop approval + vault fills without credential exposure — is the cleanest pattern published so far. If you're building any agent that touches authenticated web services, this is worth understanding as a design reference even before integrating the SDK.
