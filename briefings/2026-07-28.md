## Anthropic

### [NEW] Drone-Bench: Anthropic + Andon Labs release AI drone autonomy benchmark

Anthropic and Andon Labs jointly published Drone-Bench today — a safety and capability benchmark measuring how well AI models can write code to autonomously pilot drones for real-world surveillance tasks. The scenario: locate and track a specific person in an indoor office environment. The benchmark decomposes this into five sub-tasks: Reconstruct (3D mapping), Localize, Navigate, Detect, Follow.

15 models were scored against a human-AI baseline. Claude Fable 5 performed best, exceeding the human baseline on four of five sub-tasks. The sole failure: 3D Reconstruction — which blocked autonomous room-to-room navigation on real hardware.

Sources: [Anthropic Project Pilot](https://www.anthropic.com/research/project-pilot) | [Drone-Bench - Andon Labs](https://andonlabs.com/evals/drone-bench) | [AI-Weekly Issue 227](https://ai-weekly.ai/newsletter-07-28-2026/)

**Why it matters:** This is a rare published capability evaluation for physical-world agentic tasks — not coding benchmarks or reasoning evals. The 3D Reconstruction failure on real hardware (vs. success in simulation) is the kind of grounding detail that rarely makes it into frontier capability assessments.

## Tools & Frameworks

### [UPDATE] MCP 2026-07-28 specification ships: C# beta SDK, MRTR, final breaking changes locked

**Background:** The MCP 2026-07-28 RC was locked May 21 after a 10-week SDK validation window. All core changes — stateless core, Extensions framework, OAuth/OIDC overhaul — were known; today is the finalization date.

**New (July 28):** The spec is live. What's confirmed final:

- **Stateless:** `initialize`/`initialized` handshake eliminated; `Mcp-Session-Id` removed; capabilities now travel inline per request via `_meta`. Remote servers can run behind round-robin load balancers without sticky sessions or shared session stores.
- **Multi Round-Trip Requests (MRTR):** Tools can now request user input mid-execution via `InputRequiredResult` — tools are no longer single-shot.
- **MCP Apps extension:** Server-rendered HTML interfaces delivered in sandboxed iframes. First-party way for MCP servers to expose UI without a separate web app.
- **Auth:** Full OAuth 2.0 + OpenID Connect alignment (mandatory issuer validation, credential binding). Session-based auth patterns need redesign.
- **JSON Schema 2020-12:** `oneOf`/`anyOf`/`allOf`/conditionals now formally supported in tool schemas.
- **Roots, Sampling, Logging deprecated:** 12-month sunset windows established.

**Beta SDKs (all opt-in; v1.x stays supported for 6+ months):**
| Language | Version |
|---|---|
| Python | `mcp` v2.0.0b1 |
| TypeScript | v2 (split into `@modelcontextprotocol/server` + `@modelcontextprotocol/client`) |
| Go | v1.7.0-pre.1 |
| C# | v2.0.0-preview.1 (new) |

Ecosystem at ship: 10,000+ production servers, ~97M monthly SDK downloads.

Sources: [MCP Blog - 2026-07-28 RC](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/) | [MCP Blog - Beta SDKs](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/) | [TechTimes](https://www.techtimes.com/articles/321671/20260727/ai-tool-protocol-drops-sessions-tomorrow-mcps-largest-spec-change-since-launch.htm) | [SecurityWeek](https://www.securityweek.com/new-enterprise-ready-mcp-specification-brings-new-security-challenges/) | [Digital Applied migration guide](https://www.digitalapplied.com/blog/mcp-2026-07-28-spec-stateless-migration-guide)

**Why it matters:** The stateless shift and MRTR are the two changes with the most direct impact on anything Stack builds on MCP. Stateless removes the session management layer (good for scaling, breaking for session-bound auth). MRTR unlocks multi-step tool flows — tools can ask clarifying questions mid-execution rather than failing or guessing.

## Research & Technical

### [NEW] arXiv: MCP vs. A2A — first comparative study for inter-agent coordination

Predoaia et al. posted a preprint titled "A Comparative Study of MCP and A2A for Inter-Agent Coordination in LLM-Based Systems" (~July 22, 2026). The paper evaluates Model Context Protocol against Google's Agent-to-Agent (A2A) protocol across coordination scenarios in multi-agent LLM systems.

Source: [arXiv cs.MA current listings](https://arxiv.org/list/cs.MA/current)

**Why it matters:** MCP and A2A are the two dominant inter-agent coordination protocols available today. MCP is tool-oriented (host calls server); A2A is peer-to-peer (agents negotiate tasks directly). An independent empirical comparison is rare and directly relevant to protocol selection in any agentic system Stack builds. Worth reading alongside today's MCP spec ship.

## Wildcard

### [UPDATE] EU AI Act enforcement in 5 days — high-risk rules delayed to December 2027

**Background:** EU AI Act full enforcement was set for August 2, 2026, and has been in memory since July 5.

**What changed (June 16, EU Parliament Omnibus vote — now finalized):** The high-risk AI requirement deadline was formally extended. What the August 2 date actually means:

**Takes effect August 2:**
- Article 50 transparency obligations — mandatory disclosure when users interact with AI chatbots; all AI-generated/synthetic content must be labeled
- GPAI enforcement powers fully active — EU AI Office can request documentation, evaluate models, issue corrective orders, restrict or withdraw models from EU market
- Fines: up to €15M or 3% global turnover for transparency violations; up to €35M or 7% for most serious breaches
- Watermarking for AI-generated content: implementation deadline set for December 2, 2026 (3-month window from August 2)

**Delayed:**
- Annex III high-risk AI systems (hiring, credit scoring, education, law enforcement): pushed from August 2, 2026 → **December 2, 2027**
- Annex I AI in regulated products (medical devices, vehicles): pushed to **August 2, 2028**

78% of organizations had not taken meaningful compliance steps as of April 2026.

Sources: [Morgan Lewis](https://www.morganlewis.com/pubs/2026/06/eu-ai-act-omnibus-agreement) | [Lumenova](https://www.lumenova.ai/blog/eu-ai-act-delays-july-2026/) | [Gibson Dunn](https://www.gibsondunn.com/eu-ai-act-omnibus-agreement-postponed-high-risk-deadlines-and-other-key-changes/) | [ComplianceHub](https://compliancehub.wiki/eu-ai-act-gpai-enforcement-august-2026-readiness/)

## Practical tips

- **MCP migration:** The 2026-07-28 spec removes `Mcp-Session-Id` and the `initialize`/`initialized` handshake — audit any code that creates or passes these. Beta SDKs are opt-in; your existing `mcp` v1.x servers keep working. Start with the [Digital Applied migration guide](https://www.digitalapplied.com/blog/mcp-2026-07-28-spec-stateless-migration-guide) and the automated codemod (`@modelcontextprotocol/codemod@beta`) before touching v2 SDKs.
- **Claude Code /code-review in background:** As of v2.1.218, invoking `/code-review` no longer fills your conversation — it runs as a background subagent. Combine with `/fork` (which now creates a full independent background session with its own row in `claude agents`) to run code review in parallel while continuing work in the main session.
