## Anthropic

### [UPDATE] Claude Sonnet 5 promotional pricing ends August 31
**Background:** Claude Sonnet 5 launched at promotional rates of $2 input / $10 output per million tokens.

**New:** Anthropic confirmed the promotional window closes August 31, 2026. Standard pricing — $3 input / $15 output per million tokens — takes effect September 1. That's a 50% increase on input and 50% on output. If you're running cost models or budget alerts against Sonnet 5, update your figures before Sunday.

Sources: [Anthropic release notes (Releasebot)](https://releasebot.io/updates/anthropic/claude).

**Why it matters:** Sonnet 5 is the default model for most Claude API integrations today; the pricing step-up is automatic, no action required to trigger it.

### [UPDATE] Claude Code v2.1.245: model picker curation, prompt-cache TTL controls, cost accounting
**Background:** v2.1.243 (Aug 23) patched the glibc 2.44 startup crash on Arch/Fedora/Ubuntu 25.04. v2.1.245 (Aug 25) went further.

**New items in v2.1.245 not covered yesterday:**
- **`modelPicker` setting:** curate the `/model` picker with an ordered, labeled list of any model IDs — including Vertex/Bedrock IDs — appended to or replacing the built-in lineup.
- **`promptCacheTtl` / `subagentPromptCacheTtl` settings:** API-key and cloud-provider users can now hold a 1-hour prompt cache on the main conversation while subagents stay at 5 minutes (or vice versa).
- **`modelPricing` managed setting:** orgs can inject contracted per-model rates and a discount multiplier so `/cost`, the status line, and telemetry figures reflect actual negotiated pricing rather than list price.
- **claude-api skill context cost:** loading the built-in claude-api skill dropped from ~200k+ tokens to ~25k — reference docs now load on demand rather than all-at-once. Directly relevant if you invoke the skill frequently in long sessions.
- **Remote MCP reconnect:** non-interactive (`-p`) and SDK sessions now auto-reconnect or report-as-failed after a dropped remote MCP connection, instead of hanging silently.

Sources: [Claude Code changelog](https://code.claude.com/docs/en/changelog), [Havoptic v2.1.245 summary](https://www.havoptic.com/tools/claude-code).

**Why it matters:** `promptCacheTtl` split is useful for agent harnesses where subagent prompts are short-lived but the main orchestrator context is expensive. `modelPricing` matters for teams with enterprise discounts who want accurate `/cost` readouts.

### [UPDATE] Claude Managed Agent Platform adds advisor models, geo pinning, GitHub-hosted skills
**Background:** Claude Managed Agents (hosted sandboxes with lifecycle management) launched in stages through mid-2026.

**New:** The developer platform now exposes: session budget controls (cap total tokens per agent session), advisor models (a separate smaller model that vets agent steps before execution), inference geo pinning (lock compute to a specific region for data-residency), and GitHub-hosted skills (point a skill at a GitHub repo path rather than bundling skill source inline).

Sources: [Anthropic developer platform release notes](https://releasebot.io/updates/anthropic/claude-developer-platform).

**Why it matters:** Geo pinning + session budgets are the two blockers most enterprise teams had for using Managed Agents in regulated industries. GitHub-hosted skills make skill versioning a normal git workflow.

**New:** Anthropic has added Claude Mythos 5 to the Security product for Enterprise customers — codebase scans, vulnerability findings, and suggested patches now run on the frontier security-focused model rather than a general-purpose one. Simultaneously, Anthropic launched the **Defender Advantage Fund**, providing credits and support to security teams using Claude Security, and began widening its Cyber Verification Program to additional organizations.

## Tools & Frameworks

### [UPDATE] Microsoft Agent Framework 1.15.0 (Python) and 1.19.0 (.NET)
**Background:** Microsoft Agent Framework 1.0 shipped in April 2026; the Harness and Hosted Agents went GA in August.

**New in 1.15.0 (Python):** A2UI (agent-to-UI event streaming) support; resilient Foundry Hosted Agent reconnection; workflow checkpoint registry updates; improved streaming, approvals, telemetry, and message handling.

## Model Releases

### [UPDATE] OpenAI o3 retires from ChatGPT today; Assistants API shuts down
**Background:** OpenAI announced a 90-day sunset for o3 in ChatGPT (started May 28) and a one-year deprecation notice for the Assistants API (given August 26, 2025).

**New:** Both deadlines land today, August 26, 2026.
- **o3 in ChatGPT:** removed from the model picker in web and mobile. The o3 API endpoint remains accessible until December 11, 2026; o3-pro stays available for Pro/higher subscribers.
- **Assistants API:** every call to `/v1/assistants`, `/v1/threads`, and `/v1/threads/runs` now returns an error — no degraded mode, no grace period, no extension. Migration target is the Responses API / Conversations API. OpenAI published a migration guide but provided no automated migration tooling.

Sources: [Forkast](https://forkast.news/openai-retired-o3-from-chatgpt-today-the-real-cost-is-the-churn-it-forces-on-everyone-else/), [OrcaRouter](https://www.orcarouter.ai/blog/o3-chatgpt-retirement-august-26), [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations).

**Why it matters:** The Assistants API shutdown is the sharper edge — any production integration still using `/v1/assistants` is broken as of today. The o3 API sunset follows December 11; if you're on o3 API (not ChatGPT), you have until then.

## Wildcard

### [NEW] Nvidia discloses Vera CPU architecture at Hot Chips 2026
Presented August 24, 2026. Nvidia gave a full architectural breakdown of **Vera**, its in-house ARM server CPU, at Hot Chips 2026.

Key details:
- **88 custom Olympus cores** on a monolithic die (no chiplets, unlike AMD EPYC/Intel Xeon).
- **Olympus core:** ARMv9.2-compatible, 10-wide decoder/dispatch, 8 integer ALUs, 6 vector/FP pipelines (SVE 128), 4 load units. Up to 1.9x IPC over AMD Turin; up to 2.3x more branch predictions per cycle.
- **Spatial multithreading:** core resources split across two pipelines; data and cache can migrate between threads dynamically — designed specifically for agentic inference workloads with variable parallelism.
- **Memory:** 1.2 TB/s bandwidth via 8× 128-bit LPDDR5X controllers (SOCAMM2 interface).
- Vera will be paired with Groq 3 LPX inference accelerators (now in full production) in the Vera Rubin platform, up to 256 LPX per rack.

Sources: [Tom's Hardware](https://www.tomshardware.com/pc-components/cpus/hot-chips-2026-nvidia-breaks-down-88-core-vera-cpu-spatial-multithreading-benchmarked-1-2-tb-s-socamm2-memory-agentic-workloads-detailed-and-more), [ServeTheHome](https://www.servethehome.com/nvidia-vera-cpu-at-hot-chips-2026/), [The Register](https://www.theregister.com/systems/2026/08/01/nvidias-vera-cpu-and-the-olympus-cores-that-power-it-deep-dive/5282056).

**Why it matters:** Nvidia is vertically integrating CPU, GPU/accelerator, and networking for AI inference racks. Spatial multithreading explicitly targeting agentic workloads suggests Nvidia is designing hardware around multi-step, variable-parallelism inference patterns — not just throughput for a single batch.
