### [NEW] Claude Fable 5.2 and Mythos 5.2 (released Nov 9 — carry-forward coverage)

Both models are configurations of a single underlying model, released November 9. Fable 5.2 is openly available; Mythos 5.2 is restricted to organizations that pass Anthropic's Cyber Verification or Life Sciences Verification program, trading standard safeguards in those domains for expanded capability. Outputs are 30% faster than the 5.1 generation. Pricing: $8 / M input tokens, $40 / M output, with a 2× fast mode. Artificial Analysis Intelligence Index v5 ranks Fable 5.2 at #1 (score 65). Anthropic claims Mythos 5.2 finds 10.2% more vulnerabilities than Claude Opus 5.5 on red-team benchmarks (vendor figures, not independently verified).

Default effort is set to medium in both Claude apps and Claude Code, so agent-loop token usage stays predictable. Sources: [9to5mac](https://9to5mac.com/2026/11/09/anthropic-upgrades-claude-with-new-fable-5-2-model-details-here/), [aiweekly](https://aiweekly.co/alerts/anthropic-ships-claude-fable-52-and-vetted-tier-mythos-52), [letsdatascience](https://letsdatascience.com/news/anthropic-releases-claude-fable-52-and-mythos-52-models-66044607).

## Tools & Frameworks

### [NEW] Claude Code 2.1.325 — security hardening and MCP reconnect fix

Released November 13, the update focuses on security, permission scoping, and reliability across terminal, VS Code, cloud sessions, and MCP integrations. The key fix for multi-server setups: an MCP server that stayed disconnected after being removed and re-added through the Agent SDK now reconnects correctly. Earlier in the month, 2.1.317 (Nov 3) added a hook option that blocks actions when an Agent SDK hook callback fails (fail-closed behavior) and made MCP consent prompts more prominent. Source: [releasebot](https://releasebot.io/updates/anthropic/claude-code), [jigarjoshi](https://jigarjoshi.in/blog/november-03-claude-code-2-1-317-mcp-security-2026/).

**Why it matters:** The fail-closed hook behavior directly affects any Claude Code routine that uses hooks for auth or spend gating — if the hook errors, the guarded action is now blocked instead of proceeding silently.

### [NEW] llama.cpp v1.0.0 — stable versioned API

llama.cpp and ggml tagged version 1.0.0 on November 14, their first stable release with a semantic versioning commitment. The key promise: the C API is now stable, and breaking changes will be gated to major version bumps. For projects embedding llama.cpp as a local inference backend (self-hosted MCP servers, edge agents), this removes the "update and rebuild everything" risk from tracking main. Source: [riorundown](https://riorundown.substack.com/p/ai-news-nov-14-2026-local-ai-ecosystem).

## Practical tips

- **Anthropic API pricing:** Fable 5.2 at $8 / $40 per M in/out tokens replaces Fable 5.1 as the primary workhorse. If your agent loop was on 5.1, re-benchmark latency — the 30% speed gain likely changes the tradeoff between fast-mode (2×) and standard.
- **Claude Code hooks:** With 2.1.317's fail-closed hook behavior, test any Agent SDK hooks that make external calls before relying on them in production routines — an HTTP timeout now blocks the guarded action rather than silently continuing.
- **llama.cpp v1.0.0:** If you've been pinning to a specific commit for API stability, you can now switch to pinning a semver tag instead.
