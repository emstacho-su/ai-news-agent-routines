### [NEW] Anthropic AI for Science event: VirBench biology benchmark + John Jumper's first appearance

Anthropic held "The Briefing: AI for Science" virtual event today (June 30, 10 AM PST), featuring Anthropic leadership, life-sciences executives, and research institutions.

**Key output — VirBench:** Paper "Paving the Way for Agents in Biology" introduces a benchmark of 120 viral sequence retrieval queries spanning 40 pathogens. Baseline accuracy: Claude Sonnet 4 at 16.9%, GPT-5.5 at 91.3%. With deterministic tool augmentation (`gget virus`): Claude Sonnet 4 jumps to 92.8%, GPT-5.5 to 99.7%. The performance delta is almost entirely from scaffolding, not model quality — a strong case that the bottleneck in biological sequence tasks is access to specialized retrieval tools, not general intelligence.

**John Jumper:** First public appearance since leaving DeepMind (June 20). Nobel 2024, AlphaFold co-creator. No role title yet announced at Anthropic.

**Why it matters:** The 16.9% → 92.8% jump from a single deterministic tool call is a direct demonstration of the agent-scaffolding > base-model argument. For Stack building with Claude Code + MCP: this pattern (wrap a domain-specific deterministic function as an MCP tool, observe outsized gains) generalizes well beyond biology.

Sources: [Anthropic event](https://www.anthropic.com/events/the-briefing-ai-for-science-virtual-event), [byteiota biology agents](https://byteiota.com/anthropic-ai-for-science-biology-agents/), [AIToolsRecap June 30](https://aitoolsrecap.com/Blog/ai-news-june-30-2026), [Digital Applied](https://www.digitalapplied.com/blog/john-jumper-joins-anthropic-ai-for-science-2026)

Today is Microsoft's fiscal-year-end hard cutover date. Engineers in Experiences+Devices (Windows, M365, Outlook, Teams, Surface) are moved to GitHub Copilot CLI as of today — ending a roughly 13-month Claude Code deployment that was cancelled in May 2026.

### [NEW] Sakana Fugu Ultra: orchestrate Claude, GPT, and Gemini through one API

[Sakana AI](https://sakana.ai/fugu-release/) launched Fugu Ultra on June 22. It's a meta-agent that routes each subtask to whichever of Claude, GPT-5.5, or Gemini Omni performs best on that task type — exposing the whole system through one API endpoint. 73.7% SWE-Bench Pro; claims the orchestrated system outperforms any single constituent model on complex long-horizon coding tasks.

Pricing: $20/month subscription (Fugu + Fugu Ultra), or $5/1M input / $30/1M output on the API. Free second month if subscribed before July 31.

The structural bet: Fugu makes all three major providers interchangeable underneath. If it gains adoption, it creates pricing pressure at the inference layer and reduces lock-in — which is good for developers and bad for provider margins. Anthropic note: [Claude Pro/Max subscriptions cannot be used as Fugu backends](https://opencode.ai/); requires direct API access.

## Research & Technical

### [NEW] ICML 2026: Gradient regularization against reward hacking in RLHF + verifiable rewards

Paper (Ackermann, Noukhovitch, Ishida, Sugiyama) at ICML 2026: "Gradient Regularization Prevents Reward Hacking in Reinforcement Learning from Human Feedback and Verifiable Rewards." Proposes adding gradient regularization during RLHF training to prevent reward hacking without relying solely on KL divergence constraints, which can be gamed.

Common reward-hacking failure modes the paper targets: reasoning without actually solving, meaningless repetitions, incorrect intermediate logic, and "implicit reward hacking" where models exploit proxy signals while appearing to reason correctly.

**Why it matters for Stack's security work:** Reward hacking in cybersecurity models (vulnerability finders, exploit generators) is a safety failure by definition — a model that games its training signal while appearing capable would be discovered only in deployment. This line of research is directly relevant to evaluating how much to trust Mythos-class security results.

Sources: [ICML 2026](https://icml.cc/virtual/2026/events/2026SpotlightPosters), [arXiv related](https://arxiv.org/pdf/2601.04805)
