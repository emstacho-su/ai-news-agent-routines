## Tools & Frameworks

### [NEW] MCP 2026-07-28 specification RC: stateless core, Extensions, Tasks, MCP Apps, OAuth/OIDC

RC locked May 21; final spec ships July 28. Announced by lead maintainers David Soria Parra and Den Delimarsky. This is the largest revision since MCP launched.

**Stateless core (biggest breaking change):**
- `initialize`/`initialized` handshake **removed entirely** (SEP-2575).
- `Mcp-Session-Id` header **removed** (SEP-2567) — no more sticky sessions.
- Protocol version, client info, and client capabilities now travel in `_meta` on every request.
- New mandatory `server/discover` RPC method that every server must implement.
- New required `Mcp-Method` and `Mcp-Name` HTTP headers for routable operations.
- Net effect: remote MCP servers run behind a standard round-robin load balancer with no shared session store required.

**Extensions framework:** modular, independently versioned opt-in capability blocks with reverse-DNS IDs. Replaces monolithic protocol versioning.

**Tasks extension** (promoted from experimental core): server returns a task handle from `tools/call`; client drives lifecycle via `tasks/get`, `tasks/update`, `tasks/cancel`. `tasks/list` removed (incompatible with stateless architecture).

**MCP Apps extension:** servers ship interactive HTML UIs rendered in sandboxed iframes on the client side, communicating over the same JSON-RPC base. Declared ahead of time so hosts can prefetch and security-review before execution.

**OAuth/OIDC hardening:** mandatory `iss` parameter validation (RFC 9207), OpenID Connect `application_type` declaration, credential binding to auth server issuer, scope accumulation on step-up. Aligns with OAuth 2.1 and OpenID Connect.

**Schema:** full JSON Schema 2020-12 support for tool schemas (composition, conditionals, `$ref`).

**Deprecations (12-month sunset window):** Roots, Sampling, and Logging are all deprecated — use tool parameters/resource URIs, call provider APIs directly, and use stderr/OpenTelemetry respectively.

**SDK status:** Python `mcp 2.0.0b1` on PyPI; TypeScript split into separate `@modelcontextprotocol/server` and `@modelcontextprotocol/client` packages at `2.0.0-beta.1`. Automated TypeScript codemod: `@modelcontextprotocol/codemod@beta v1-to-v2`. Python class rename: `FastMCP` → `MCPServer`. v1.x continues to receive security patches (at least 6 months post-GA for TypeScript).

Sources: [MCP official blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/), [MCP SDK betas post](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/), [Developers Digest migration guide](https://www.developersdigest.tech/blog/mcp-2026-07-28-breaking-changes), [WorkOS auth deep-dive](https://workos.com/blog/mcp-2026-spec-agent-authentication), [ChatForest builder guide](https://chatforest.com/builders-log/mcp-spec-2026-07-28-release-candidate-stateless-breaking-changes-builder-guide/).

**Why it matters:** Direct impact on the Resend MCP server (Phase R2). If it runs as a remote server with any session state, it needs to be refactored to the stateless model before July 28. The Tasks extension is also relevant for the long-running routine trigger patterns in this repo.

### [NEW] Google Gemini API Managed Agents: background tasks, remote MCP, free tier (July 7)

Google announced four major additions to its Managed Agents product in the Gemini API on July 7 (Logan Kilpatrick announcement):

1. **Background task execution** (`background: true`): agents run async without holding an HTTP connection; returns an `interaction_id` for polling or streaming. Designed for long-running agent workloads.
2. **Remote MCP server integration**: agents can attach to private/external MCP servers (not just the built-in code execution and Google Search sandbox tools).
3. **Custom function calling**: client-side business logic can pause an interaction mid-run, execute locally, and resume with the result.
4. **Network credential refresh**: OAuth tokens and API keys can be rotated between interactions by passing an existing `environment_id` with a new network config; sandbox filesystem (packages, repos, files) is preserved.

The sandbox is free during preview; model inference bills at standard Gemini rates. History retention is 1 day on the free tier vs. 55 days on paid. The underlying agent is "Antigravity," built on Gemini 3.5 Flash. SDK: `google-genai >= 2.0.0` (Python) and `@google/genai >= 2.0.0` (JavaScript/TypeScript).

Sources: [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/expanding-managed-agents-gemini-api/), [The Decoder](https://the-decoder.com/google-deepmind-adds-background-execution-and-mcp-support-to-gemini-api-managed-agents/), [NxCode production guide](https://www.nxcode.io/resources/news/gemini-managed-agents-background-remote-mcp-production-guide-2026).

**Why it matters:** Google now matches Claude's Managed Agents capability set on background execution and MCP attachment. Free tier access lowers the barrier to compare them head to head.
