## Anthropic

### [NEW] Anthropic builds in-house chip team to co-design silicon for Claude

Anthropic confirmed on August 5 that it is assembling a dedicated custom silicon team, with open roles spanning front-end design, physical design, pre-silicon verification, analog/mixed-signal, and packaging. The stated goal is to co-design Claude model architectures with chip architecture simultaneously — letting attention mechanisms and sparsity patterns drive silicon choices rather than the reverse. Anthropic's stated target is ~50% reduction in per-token inference costs; no timeline or manufacturing partner was announced, and existing supply agreements with AWS, Google, Nvidia, and AMD remain in place. Industry analysts put the design cost of an advanced AI chip near $500M, so this is a multi-year bet.

**Why it matters:** If Anthropic closes even a 30–40% cost gap through co-design, it changes the unit economics for long-context and agentic workloads — the ones Stack's projects actually stress. Worth tracking the hire cadence as a leading signal of timeline.

### [NEW] Claude Enterprise inference hooks: prompt-level DLP in beta

Anthropic launched inference hooks in beta for Claude Enterprise on August 5. The feature routes every employee prompt and tool call response through the customer's own security server for an allow-or-deny verdict before the model processes it — the same pattern enterprise DLP teams already use on email and web traffic, now applied to Claude chat, Claude Code, Claude Cowork, and MCP connectors in a single org-level configuration. Deployment controls include shadow mode (log-only, no blocking), percentage-based rollout, and role-based exclusions.

**Why it matters:** For Stack's security concentration: this is the first Anthropic-native control plane that lets an enterprise enforce data-handling policy at inference time without modifying prompts or post-processing responses. The architecture is essentially a man-in-the-middle you own.

Sources: [Anthropic Blog](https://claude.com/blog/claude-enterprise-inference-hooks), [Unite.AI](https://www.unite.ai/anthropic-puts-inline-data-loss-prevention-inside-claude-enterprise/), [The Next Web](https://thenextweb.com/news/anthropic-inference-hooks-dlp-claude-enterprise)

### [UPDATE] Claude Code v2.1.221: Focus view and 39 fixes

**Background:** v2.1.139 shipped /goal, agent view, and fallbackModel in late July/early August.

**New:** v2.1.221 (released August 4) adds Focus view — a toggle (Ctrl+Alt+F or "Claude Code: Toggle Focus view" command in the chat menu) that collapses per-turn tool activity into an expandable summary with a live running-tool indicator. Addresses the biggest UX complaint on long-running agentic tasks: constant scroll through search/read/tool-return noise. The release also includes 39 bug fixes: stronger worktree isolation (subagents of worktree sessions can no longer run destructive git commands on the main checkout), auto-allow security hardening, improved proxy/timeout behavior, cleaner usage reporting, and re-enabled tool search on Vertex AI for Claude 4.5+ models. Separately, Anthropic extended the 50% weekly usage boost for Claude Code Max subscribers through August 19; Claude Sonnet 5 promo pricing ends August 31 (standard pricing effective September 1).

Sources: [Havoptic](https://www.havoptic.com/tools/claude-code), [DevelopersIO](https://dev.classmethod.jp/en/articles/20260804-cc-updates-v2-1-221/), [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

## Tools & Frameworks

### [UPDATE] Microsoft Agent Framework Harness + Hosted Agents reach GA

**Background:** Microsoft Agent Framework 1.0 launched as production-ready and MCP-native in late July.

**New:** The Agent Harness component (skills, memory, middleware lifecycle) and Foundry Hosted Agents have both reached general availability in August, completing the framework's trajectory from developer SDK to governed production runtime. Harness runs as a single binary across local dev, containers, and hosted deployment; Hosted Agents add sandboxed sessions, managed state, and filesystem access. Python release 1.13.0 and dotnet 1.17.0 shipped in the same cycle with Durable Task and Azure Functions integration plus workflow replay fixes.

**Why it matters:** The Harness GA is the handoff point where framework capability meets operational maturity — teams can now run multi-agent workflows in production on Microsoft infrastructure with audit trails and approval gates baked in, not bolted on.

Sources: [InfoQ](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/), [Nerd Level Tech](https://nerdleveltech.com/agent-harness-ga-microsoft-agent-framework), [devblogs.microsoft.com](https://devblogs.microsoft.com/agent-framework/the-microsoft-agent-framework-harness-is-now-released/)

### [NEW] MCP C# SDK v2.0: stable alignment with 2026-07-28 spec

The official MCP C# SDK reached v2.0.0, bringing it into stable alignment with the 2026-07-28 MCP specification (stateless-first protocol, Multi Round-Trip Requests for interactive tools, standardized HTTP headers, discovery-first negotiation, caching hints, stronger OAuth and token-cache safety). Two new extension packages — MCP Apps and MCP Tasks — ship alongside the core SDK. The release is backward compatible. Enterprise-Managed Authorization (EMA) — zero-touch OAuth that lets org admins configure MCP server access once via their existing identity provider — was promoted from preview to stable alongside this release.

**Why it matters:** C# SDK v2.0 + EMA stable means the .NET/Azure side of the MCP ecosystem is now production-grade. EMA specifically eliminates per-developer API key paste-and-forget, which was the dominant MCP security complaint in enterprise rollouts.

Sources: [GitHub Release](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.0.0), [.NET Blog](https://devblogs.microsoft.com/dotnet/announcing-v20-of-the-official-mcp-csharp-sdk/), [MCP Blog: EMA](https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/)
