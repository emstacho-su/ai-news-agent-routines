## Anthropic

### [NEW] 2026 Usage Policy update: cruelty ban, expanded weapons scope, narrowed election rules — effective Nov 12

Anthropic published its annual usage policy update on October 8; it takes effect November 12, 2026. Four substantive changes:

1. **Cruelty rule:** The policy now prohibits "sustained and needless abusive or cruel behavior toward our models." Standard user frustration, creative dark themes, and model testing / red-teaming are explicitly carved out — the rule targets prolonged targeted harassment, not normal pushback or research workflows.
2. **Weapons scope expanded:** The prohibition on weapons software now explicitly covers arming autonomous vehicles and drone systems.
3. **Law enforcement:** Claude may not be used to recommend whom police agencies should investigate, arrest, or charge.
4. **Elections re-scoped:** The section is renamed "Do Not Undermine Democratic Processes." The blanket ban on personalized campaign targeting is removed; the focus shifts to voter deception, impersonation of candidates/officials, and turnout suppression. Anthropic said removing the targeting ban avoids capturing legitimate civic uses such as multilingual ballot-cure notices.

Most changes are described by Anthropic as clarifications of existing intent rather than new prohibitions.

## Tools & Frameworks

### [UPDATE] Claude Code v2.1.292: marketplace flag, Agent effort param, UNC-path security fix

**Background:** v2.1.289 (Oct 6) fixed terminal freeze on short code blocks with many unclosed tags, added `agent.spawn` API, and fixed hook/plugin policy enforcement.

**New in v2.1.292 (Oct 6-7):**
- `claude plugin install --marketplace <source>`: adds the marketplace source if needed, applies policy checks, then installs. Streamlines one-liner plugin installs from community sources.
- **Effort parameter on Agent tool:** sub-agents now run at the effort level you specify in the Agent tool call (previously, effort was only settable in sub-agent frontmatter).
- **Security fix:** PreToolUse hook approvals and auto mode no longer bypass the permission prompt for file reads from UNC (network) paths (`\\server\share`).
- **MCP tool name guard:** an MCP server advertising a tool with a name exceeding 128 characters no longer crashes every request — the offending tool is silently dropped and an MCP error is logged.
- `NO_PROXY` is now respected for Claude Code's own API requests when `HTTPS_PROXY` is set.

## Model Releases

### [UPDATE] GPT-5.5 retirement in 3 days (Oct 14): what breaks, what doesn't

**Background:** OpenAI announced in September that GPT-5.5 would retire from ChatGPT, ChatGPT Work, and Codex on October 14, 2026, across all plan tiers (consumer, Business, Enterprise, Edu). API access is unaffected.

**New — actionable specifics:**
- **Codex users:** Anyone accessing Codex via ChatGPT sign-in (not API key) needs to manually switch to `gpt-5.6-sol` before Oct 14. OpenAI has confirmed no automatic migration and no behavioral parity guarantee.
- **What breaks:** workspace defaults, saved model settings, managed configurations, custom GPT agents configured to GPT-5.5 by model ID, and scheduled tasks that hard-code the model identifier.
- **Replacement options:** GPT-5.6 Sol is OpenAI's named like-for-like; GPT-6 Astra for harder multi-step work; GPT-5.6 Terra as a lightweight everyday option.
- **API/key-authenticated access:** continues past Oct 14 with no change.

**Why it matters:** If you have Codex workflows, automated scripts, or custom agents that select GPT-5.5 by ID, you have 3 days to test against a replacement.

Sources: [letsdatascience.com](https://letsdatascience.com/news/openai-retires-gpt-55-from-chatgpt-and-codex-1a6f69be), [aiidelist.com](https://aiidelist.com/blog/gpt-5-5-retirement-october-14), [orcarouter.ai](https://www.orcarouter.ai/blog/gpt-5-5-remains-available-openai-api-codex-api-key), [azat.tv](https://azat.tv/en/openai-retires-gpt-5-5-october-14/)

## Practical tips

- The cruelty rule in Anthropic's updated usage policy includes explicit research/testing carve-outs, so red-teaming and adversarial eval workflows should be unaffected. For production use cases that involve frustration simulation or dark creative themes, document the purpose — the rule targets "sustained and needless" patterns, not edge-case testing.
- Claude Code v2.1.292's effort parameter on the Agent tool is a direct lever for cost control in multi-agent pipelines: route simple subagents to `low` effort and reserve `high` or `max` for the steps that actually need it.
- If you're running MCP servers from community sources, the 128-char tool name guard means a misconfigured server no longer silently breaks your whole session — check your logs for MCP errors after updating.
