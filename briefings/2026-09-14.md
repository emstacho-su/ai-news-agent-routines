## Anthropic

### [UPDATE] Amodei's "Pace the Frontier" essay — first concrete actions land

**Background:** On September 12, Anthropic CEO Dario Amodei published "We Must Pace the Frontier," calling for a deliberate slowdown in capability gains so safety work can keep up. Altman and Musk publicly backed it the same day; Anthropic researcher Jacob Coxon's public resignation raised internal credibility questions.

**New:** Anthropic has announced it will unilaterally give METR (Model Evaluation and Threat Research) permanent, employee-level system access — independent verifiers who can confirm safety commitments are actually being met rather than just claimed. Within hours, OpenAI CEO Sam Altman publicly pledged OpenAI would do the same. Google DeepMind's Hassabis tied his endorsement to the standards body talks (see next item). Anthropic presented this as "step 1" of Amodei's three-part plan.

Sources: [TechCrunch](https://techcrunch.com/2026/09/12/anthropic-ceo-outlines-plan-to-pace-the-frontier/), [Winzheng](https://www.winzheng.com/en/article/amodei-pace-the-frontier-ai-slowdown-third-party-evaluation), [Dealroom](https://app.dealroom.co/news/note/dario-amodei-we-must-pace-the-frontier-anthropic-commits-to-embedded-third-party-evaluators)

**Why it matters:** METR gets read access to weights, evals, and internal tooling — not just a brief red-team window. If this pattern holds across labs it's a real governance shift, not a press release.

### [NEW] Google/OpenAI/Anthropic in formal talks to create AI standards body

Representatives from all three labs have been meeting since July on a proposal to create an industry-wide standards organization for frontier AI, per The Information (Sept 13). The talks are led by Amodei, with Altman's support. Hassabis has publicly backed the direction and wants the organization operational before end of 2026. Core scope: shared protocols for pre-release testing, independent safety evaluations, and standardized risk assessments before deploying frontier models. The proposal is distinct from the existing four-company jailbreak scoring framework (which targeted narrower vulnerability disclosures) — this is a broader governance body.

[RUMOR] A draft charter is reportedly circulating; no final structure confirmed.

Sources: [The Information](https://www.theinformation.com/articles/inside-ai-industrys-behind-scenes-push-police), [PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2026/google-openai-and-anthropic-float-idea-of-ai-standards-body), [Kingy AI](https://kingy.ai/news/openai-google-anthropic-ai-standards-body/), [AI Weekly](https://aiweekly.co/alerts/anthropic-openai-google-meet-since-july-on-ai-standards-body)

## Wildcard

### [NEW] Microsoft publishes MAI model Code of Conduct for public consultation

Microsoft released its first-party model behavioral guidelines today (Sept 14), announced by Satya Nadella on Sept 13 in direct response to Amodei's essay. Core position: "Any pursuit of superintelligence has to be grounded in the core principle that if the AI we build is not helping humanity and under human control, it's not worth pursuing." Microsoft frames its approach around three pillars: broad access/choice at every layer, enterprise control of learning loops, and the new behavioral guidelines for MAI models. The document is open for public consultation — an unusual step for Big Tech. Nadella used the phrase "deliberate pacing" in a positive framing, contrasting with Trump's "whoever wins AI, wins."

Sources: [Unite.AI](https://www.unite.ai/nadella-announces-public-consultation-on-microsofts-mai-model-rules/), [Dataconomy](https://dataconomy.com/2026/09/14/satya-nadella-says-superintelligence-must-remain-human-controlled/), [Kingy AI](https://kingy.ai/news/microsoft-ai-code-of-conduct-nadella-human-control/)

### [UPDATE] DeepSeek silently re-routes V4-Pro API to V4.1-Flash starting today

**Background:** deepseek-v4-pro (the Aug 12 GA build) has been the default production endpoint since August, with peak/off-peak pricing.

**New:** Starting 04:00 UTC September 14, all `deepseek-v4-pro` requests route to V4.1-Flash, at V4.1-Flash pricing. V4.1-Flash adds native visual input and is the smallest V4.1 architecture model. The model string `deepseek-flash` (no version number) is now the canonical alias. Code pinned to `deepseek-v4-pro` keeps answering without changes; V4-Pro service extended past Sept 14 due to user demand with billing unchanged. V4.1-Pro (the next full reasoning model) has no confirmed ship date.

Sources: [DeepSeek API docs](https://api-docs.deepseek.com/news/news260910/), [Pandaily](https://pandaily.com/deepseek-v4-pro-api-routes-to-v41-flash-sept-14), [SuperPower Daily](https://superpowerdaily.com/posts/deepseek-launches-v4-1-flash-and-plans-to-replace-v4-pro-api-traffic)

**Why it matters:** If you're using deepseek-v4-pro in any project, your cost basis just changed under you. Worth checking the pricing page before tomorrow.
