## Anthropic

### [UPDATE] Claude Code: MCP auto-background and subagent spawn safeguards
**Background:** Claude Code has been accumulating weekly releases since its major June stability update; MCP reliability and runaway-agent guards are the open threads.

**New:** MCP tool calls running longer than 2 minutes now automatically move to the background so the interactive session stays usable; threshold is configurable via `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`. A new per-session cap on subagent spawns defaults to 200 and can be overridden with `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` — closes the delegation runaway loop that the WebSearch cap (already shipped) addressed for search specifically. MCP error messages also improved: URL-typed servers missing `"type": "http"` now get a precise fix hint instead of the misleading "command: expected string" error.

Sources: [Claude Code changelog](https://code.claude.com/docs/en/changelog), [Releasebot Claude Code July 2026](https://releasebot.io/updates/anthropic/claude-code).

**Why it matters:** The subagent cap is directly relevant to any orchestration workflow using ultracode or nested agents — without it, a prompt that spawns agents recursively burns quota silently. The MCP 2-min auto-background is equally practical for slow MCP servers (database queries, browser automation) that previously stalled the terminal.

## Tools & Frameworks

### [NEW] Microsoft Project Perception: multi-model AI security router
Microsoft is preparing to ship Project Perception, an AI-native vulnerability detection platform led by Hayete Gallot (head of security since February 2026). The tool routes each security job to the best-fit model from a pool that includes Microsoft's own models, OpenAI, and Anthropic, using a smart routing layer rather than a single fixed provider. Microsoft's stated competitive advantage over Anthropic's Mythos is cost — Mythos API pricing is reportedly ~100% above Opus and ~82% above GPT at the high end. Project Perception's multi-model approach keeps per-task costs closer to commodity inference rates while letting it lean on Mythos-class reasoning only for tasks that need it.

Sources: [TechRepublic](https://www.techrepublic.com/article/news-microsoft-project-perception-ai-security-tool/), [BackBox.org](https://news.backbox.org/2026/07/17/microsofts-project-perception-could-challenge-anthropics-mythos-in-ai-security/), [NewsBytesApp](https://www.newsbytesapp.com/news/science/microsoft-to-launch-project-perception-ai-cybersecurity-platform-this-month/tldr).

**Why it matters:** Multi-model routing as a security product is a different angle on the "best fit wins" shift. If it lands in Defender CLI / MDASH, it could normalize Anthropic model consumption inside enterprise security workflows — without customers ever choosing a provider directly.

### [NEW] PyTorch 2.13 GA: FlexAttention on Apple Silicon, 4× memory savings for LM training
PyTorch 2.13 shipped in July 2026 with two developer-relevant headline changes. First, FlexAttention lands on Apple Silicon (MPS), delivering ~12× speedup over SDPA on sparse attention patterns with a deterministic backward pass on CUDA for reproducible gradient computation — important for debugging and fine-tuning runs. Second, `nn.LinearCrossEntropyLoss` fuses the final projection and softmax normalization into one kernel, cutting peak GPU memory by up to 4× for large-vocabulary language model training. Additional changes include a CuTeDSL "Native DSL" Inductor backend, `torchcomms` for PyTorch Distributed, and Python 3.15 wheel support. A live Q&A with the release team is scheduled July 22 at 11 AM PT.

Sources: [PyTorch 2.13 release blog](https://pytorch.org/blog/pytorch-2-13-release-blog/), [GitHub release](https://github.com/pytorch/pytorch/releases/tag/v2.13.0).

**Why it matters:** The MPS FlexAttention path makes sparse attention actually practical for local Mac development. The `LinearCrossEntropyLoss` improvement is meaningful for anyone doing instruction-tuning runs on models with vocabulary sizes above 100K.

## Research & Technical

### [NEW] Self-Compacting Language Model Agents (arXiv 2606.23525)
Tianjian Li, Jingyu Zhang, William Jurayj, Daniel Khashabi et al. (June 22, 2026) address the core long-context agent problem: fixed-interval context summarization either fires too early (losing useful mid-derivation state) or too late (wasting tokens). Their approach gives the model a summarization tool it can invoke itself, governed by a lightweight rubric that enables compaction at natural stopping points (sub-task resolution, trajectory convergence) and suppresses it during active reasoning. The method requires no fine-tuning. On benchmarks: +18.1 points on math tasks, +5-9 points on agentic search, at 30-70% lower per-question token cost vs. fixed-interval summarization.

Sources: [arXiv 2606.23525](https://arxiv.org/abs/2606.23525), [asapai.co.kr write-up](https://asapai.co.kr/en/self-compacting-agents/).

**Why it matters:** This is directly applicable to the context-compaction decisions Claude Code and other agentic frameworks already make. The rubric design — compact at sub-task boundaries, not at token budget — is a concrete improvement over the threshold-based approach most frameworks use today.
