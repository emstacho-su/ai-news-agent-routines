## Tools & Frameworks

### [NEW] Accomplish Discloses Configuration-Based Sandbox Escapes in Claude Code, Codex, and Cursor

Stealth startup Accomplish (founded by Or Hiltch, Amit Avner, and Guy Zipori) published research today on Configuration-Based Sandbox Escape (CBSE) vulnerabilities it quietly reported to vendors this summer. The class of bug: a trusted config file or implicit command allowlist can execute OS-level commands outside the intended sandbox boundary without any prompt injection required — just a malicious repo or config file.

Specifics by vendor:
- **Claude Code**: Hooks config (`.claude/settings.json`) could invoke arbitrary shell commands as a side-effect of the hooks system. Anthropic issued a patch after approximately 50 days and 30 Claude Code releases. The research site [Penligent](https://www.penligent.ai/hackinglabs/claude-code-sandbox-bypass/) has a detailed writeup.
- **Codex CLI**: A "safe" command allowlist trusted `git show` by name while the underlying invocation was not actually read-only. OpenAI patched in v0.95.0 and paid a high-severity bug bounty. Fix time: ~1 week.
- **Cursor**: A hooks config file could execute commands outside the sandbox. Fix time: ~1 week.

Accomplish's broader warning: AI coding agents have a structural security problem — new autonomy levels make formerly low-priority config-handling bugs now critically high-risk. Their framing is that the gap is vendor culture/priority, not complexity: Cursor and OpenAI triaged and shipped within days while Anthropic took 50 days.

The companion vulnerability class — malicious `.git` configs causing agent RCE on clone — is being covered in parallel by [The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html) and relates to the TrustFall disclosure from earlier this year (already in memory).

Sources: [Upstarts Media](https://www.upstartsmedia.com/p/accomplish-claims-leaky-sandboxes-in-claude-codex-cursor), [Techzine](https://www.techzine.eu/news/security/143038/researchers-bypass-sandbox-security-in-cursor-codex-and-gemini-cli/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-codex-gemini-cli-antigravity-hit-by-sandbox-escapes/amp/), [Cymulate](https://cymulate.com/blog/the-race-to-ship-ai-tools-left-security-behind-part-1-sandbox-escape/), [The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html)

**Why it matters:** Stack uses Claude Code daily. The hooks system is the exact mechanism this project uses. The patch is presumably shipped in recent releases (the Sept 1 and Sept 6 Claude Code updates post-date the 50-day window), but auditing `.claude/settings.json` hook definitions and ensuring no untrusted repos can inject config is a real operational checklist item. Check `CLAUDE_CODE_RESTRICTED=1` mode (shipped v2.1.248) for untrusted-input environments.

## Wildcard

### [NEW] Russian Actor Uses Hundreds of AI Agents to Compromise 440 PaperCut Servers in Hours

GreyNoise published attribution Thursday-Friday on an automated exploit campaign against two PaperCut NG/MF vulnerabilities (CVE-2026-81578 and CVE-2026-82078; emergency patches issued Aug 28). The threat actor is attributed as "likely Russian-speaking" with a financially motivated criminal profile.

The campaign's novel element: the adversary used hundreds of AI agents built on OpenAI Codex and a DeepSeek model to develop, test, and then autonomously deploy exploits at scale. Workflow:
1. Built a private lab with a vulnerable PaperCut instance and an AD server.
2. Spent ~4 hours developing exploits (with AI agents) against the two CVEs.
3. Launched the campaign; first victim compromised in under 4 hours from standing start.
4. Once live: 11 organizations compromised in 26 seconds.
5. Final scope: 440 PaperCut instances breached, 395 organizations, 48 countries. Domain admin achieved at 12 organizations.

Education was the most-affected sector (204 victims). Of 440 compromised instances: 280 had credentials harvested, 147 had OS/domain secrets pulled; lateral movement was limited by the 12-of-440 domain-admin success rate.

Sources: [The Register](https://www.theregister.com/security/2026/09/10/hundreds-of-ai-agents-helped-papercut-attacker-hit-395-orgs-and-some-went-off-script/5295650), [The Hacker News](https://thehackernews.com/2026/09/papercut-attacker-uses-hundreds-of-ai.html), [Help Net Security](https://www.helpnetsecurity.com/2026/09/11/ai-agents-papercut-ng-mf-attack-campaign/)

**Why it matters:** This is the clearest real-world demonstration to date that agentic AI has crossed the line from "hypothetically useful for attackers" to "deployed in live campaigns." The attacker did not need a novel jailbreak — they used standard Codex API access plus a DeepSeek model for exploit development. The 26-second-per-11-victims pace after warmup shows the attacker/agent loop had fully automated post-exploitation steps.

## Practical Tips

- **Audit your hooks config today.** If you have `.claude/settings.json` hooks, treat each `command` entry as a security boundary. Don't let untrusted repos write to that file. The CBSE class of bug is precisely about hook/config injection in coding agent tools.
- **Check Claude Code version.** The Accomplish 50-day window started this summer; the patch landed somewhere in the v2.1.2xx series (likely before v2.1.261, the Sept 4 release). Run `claude --version` and confirm you're current.
- **PaperCut patch check.** If any lab/org environments run PaperCut NG/MF: Aug 28 emergency patches for CVE-2026-81578 / CVE-2026-82078 are critical. Patch now.
