## Anthropic

### [UPDATE] Mythos: 10,000+ critical flaws found; Bloomberg asks why Anthropic is expanding a tool it calls dangerous

**Background:** Claude Mythos is Anthropic's vulnerability-discovery model, described as too dangerous for general public release. An initial cohort of ~50 partners (including US government agencies) gained access in April to scan codebases.

**New:** The initial 50 partners have already uncovered more than **10,000 "high or critical severity"** security flaws. On June 2, Anthropic expanded access to ~150 additional organizations across 15+ countries (Australia, Canada, France, Germany, India, Japan, South Korea, and others), focusing on critical infrastructure in power, water, healthcare, and communications — bringing the total organization count to roughly 200. Bloomberg published a June 9 piece directly naming the contradiction: Anthropic's own framing is that Mythos is too dangerous for general release, yet the distribution keeps growing.

Sources: [Bloomberg (June 9)](https://www.bloomberg.com/news/articles/2026-06-09/anthropic-calls-mythos-dangerous-why-is-it-expanding-access), [CNBC (June 2)](https://www.cnbc.com/2026/06/02/anthropic-mythos-ai-project-glasswing.html), [TechCrunch (June 2)](https://techcrunch.com/2026/06/02/anthropic-scales-claude-mythos-to-critical-infrastructure-in-15-countries/), [CyberScoop](https://cyberscoop.com/anthropic-project-glasswing-expansion-critical-infrastructure-claude-mythos/)

**Why it matters:** The Bloomberg scrutiny makes the governance tension explicit. The 10k+ flaw count validates capability, but a tool that finds that many critical vulnerabilities in vetted partners' infra is exactly the kind of thing regulators and hostile actors notice. Expect this framing to recur as more countries get access.

### [UPDATE] Claude billing split June 15 — programmatic usage moves to a separate API-rate credit pool

**Background:** Anthropic announced in early June that Agent SDK and `-p` usage would stop drawing from subscription limits.

**New:** Specific credit amounts by plan: **$20/mo (Pro)**, **$100/mo (Max 5x)**, **$200/mo (Max 20x)**. Programmatic usage that draws from this pool: Claude Agent SDK (Python and TypeScript), `claude -p` non-interactive invocations, Claude Code GitHub Actions, and approved third-party apps. All are metered at **full API token rates**. The credit **resets monthly with no rollover** and expires unused. Critically: it is **per-user** — CI/CD jobs running under multiple committers' credentials cannot pool credits across the team. Interactive Claude Code (terminal, IDE, web, Claude Cowork) remains on the subscription limit unchanged.

Sources: [The Decoder](https://the-decoder.com/claude-subscriptions-get-separate-budgets-for-programmatic-use-billed-at-full-api-prices/), [Build This Now](https://www.buildthisnow.com/blog/guide/mechanics/claude-billing-change-june-2026), [Codersera](https://codersera.com/blog/anthropic-june-2026-billing-change-claude-code/), [TechTimes (June 2)](https://www.techtimes.com/articles/317625/20260602/anthropic-ends-subscription-subsidy-agents-june-15-credit-pool-replaces-flat-rate-access.htm)

**Why it matters:** Direct ops impact. Any `claude -p` pipelines, Agent SDK scripts, or this repo's CI Actions consume from Stack's $200 Max credit at API rates starting June 15. If a Routine fires a programmatic call, that call counts here. Worth auditing before the cutover.

## Tools & Frameworks

### [NEW] Claude Swift package for Apple's Foundation Models framework

Anthropic released a Swift package that implements Apple's new `LanguageModel` protocol, announced at WWDC 2026. The protocol — available in iOS 27, iPadOS 27, macOS 27, visionOS 27, and watchOS 27 — defines a standard interface so an app can start with Apple's on-device model and escalate complex queries to Claude (or Gemini) by swapping a Swift Package Manager dependency. No changes to session logic, streaming setup, or tool-call handling are needed. The package accepts an Anthropic API key, handles structured outputs back into SwiftUI views, and supports streaming. Apple's design intent: prototype on-device, route to cloud only when the task exceeds on-device capability.

Sources: [Anthropic blog](https://claude.com/blog/claude-for-foundation-models), [TechTimes (June 9)](https://www.techtimes.com/articles/318039/20260609/wwdc-2026-developer-tools-foundation-models-now-swaps-ai-providers-without-code-changes.htm), [Apple Developer WWDC26 session 241](https://developer.apple.com/videos/play/wwdc2026/241/)

**Why it matters:** For iOS/macOS development, this is the lowest-friction Claude integration possible — a single SPM dependency and an API key. The provider-swap design also means you can benchmark Claude vs on-device without restructuring the app.

### [UPDATE] WWDC 2026 developer layer — LanguageModel protocol makes Claude/Gemini/on-device interchangeable via SPM

**Background:** WWDC keynote (June 8) confirmed iOS 27 with Gemini-powered Siri under Apple's Extensions system.

**New:** The Platforms State of the Union session introduced the `LanguageModel` protocol as a developer API in the Foundation Models framework — a standardized Swift interface distinct from the user-facing Extensions system. Developers can swap the AI backend (Apple on-device, Gemini, or Claude) by updating an SPM dependency with no other code changes. This is targeted at app developers, not end-users configuring Siri backends.

Sources: [TechTimes (June 9)](https://www.techtimes.com/articles/318039/20260609/wwdc-2026-developer-tools-foundation-models-now-swaps-ai-providers-without-code-changes.htm), [Apple Developer WWDC26 session 241](https://developer.apple.com/videos/play/wwdc2026/241/)

### [UPDATE] MCP 2026-07 Release Candidate — stateless core, MCP Apps (server-rendered UI), OAuth/OIDC hardening; GA July 28

**Background:** MCP roadmap transferred governance to the Linux Foundation's Agentic AI Foundation in December 2025; working groups organized around auth, extensions, and interoperability.

**New:** The 2026-07 Release Candidate is published; final GA targets July 28. Spec changes of note:
- **Stateless protocol core:** servers no longer need to maintain per-session state, enabling horizontal scaling and serverless deployments.
- **MCP Apps:** a new capability allowing MCP servers to push server-rendered UI to MCP-capable clients — the first mechanism for servers to present structured interactive surfaces beyond raw tool output.
- **Tasks extension:** graduated from experimental; Tasks now have a stable wire format for long-running async operations.
- **Auth hardening:** fully aligned with OAuth 2.1 / OpenID Connect; earlier auth approaches deprecated.

Ecosystem scale: 10,000+ public servers, 110M+ monthly SDK downloads. Security caveat: a June 2026 survey found ~40% of public MCP servers expose tools with no authentication. A VIPER-MCP sweep of ~40,000 repos produced 67 CVEs from 106 zero-days.

Sources: [AAIF MCP Dev Summit recap](https://aaif.io/blog/mcp-is-now-enterprise-infrastructure-everything-that-happened-at-mcp-dev-summit-north-america-2026/), [Medium — MCP 2026-07 deep dive](https://medium.com/@balajibal/mcps-upcoming-2026-release-is-a-big-deal-1d15990f121f), [Adversa AI security roundup](https://adversa.ai/blog/top-mcp-security-resources-june-2026/)

**Why it matters:** MCP Apps changes the game for anything using MCP servers as a UI layer — servers can now push native UI, not just data. The 40% unauthenticated stat is a meaningful ops risk if you're exposing any MCP server to the internet.

## Model Releases

### [UPDATE] MAI-Thinking-1 — Microsoft's first from-scratch reasoning model in Foundry private preview

**Background:** Microsoft announced Project Polaris (in-house MoE coding model) at Build 2026 on June 2.

**New:** MAI-Thinking-1 is the reasoning model from the same Build 2026 batch (Microsoft shipped 7 new MAI models at the event): 35B active parameters, ~1T total in a sparse MoE architecture, 256K context. Benchmarks: 97.0% AIME 2025, 94.5% AIME 2026. Surge blind side-by-sides rated it preferred over Claude Sonnet 4.6. Trained from scratch on commercially licensed enterprise data — explicitly no OpenAI distillation or third-party model knowledge transfer. Co-designed with Microsoft's Maia 200 silicon, which delivers a 1.4x efficiency gain over commodity hardware. Private preview on Microsoft Foundry today.

Sources: [Microsoft AI blog](https://microsoft.ai/news/introducing-mai-thinking-1/), [TechTimes (June 2)](https://www.techtimes.com/articles/317631/20260602/microsoft-build-2026-mai-thinking-1-first-house-reasoning-model-trained-without-openai-data.htm), [Thurrott (Build 2026)](https://www.thurrott.com/a-i/336960/build-2026-microsoft-launches-first-flagship-reasoning-ai-model-and-more)

**Why it matters:** Microsoft is no longer just a downstream distributor of OpenAI models. A self-trained frontier reasoner with its own silicon co-design is a structural shift — they can iterate on capability and cost independently. The Surge benchmark preference over Claude Sonnet 4.6 will need independent validation, but it's the claim that matters commercially.
