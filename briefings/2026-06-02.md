### [NEW] Claude 4 API hard retirement: June 15 at 9 AM PT — no failover

`claude-sonnet-4-20250514` and `claude-opus-4-20250514` stop accepting API calls on **June 15, 2026 at 9 AM PT**. Unlike typical OpenAI-style deprecations, Anthropic provides no automatic routing to a successor — requests return errors. The fix is one line: swap model strings to `claude-sonnet-4-6-20251001` and `claude-opus-4-6-20251001`.

Claude Sonnet 4.6 ships near-Opus-level coding performance, a 1M context window (beta), and substantially improved computer use. Opus 4.6 is the current production Opus.

**Why it matters:** Any integration, agent, GitHub Action, or script hardcoded to the claude-4 model strings fails silently-then-loudly on June 15. Same date as the billing split for programmatic usage (Agent SDK, `claude -p`, GitHub Actions). Two migration items converge on one deadline.

### [UPDATE] Claude Code v2.1.160 — security hardening for shell and build configs

**New since last coverage (v2.1.158):** Released today.

- **Shell startup protection:** Claude now prompts before writing to `.zshenv`, `.zlogin`, `.bash_login`, and `~/.config/git/` — prevents silent PATH manipulation or hook injection.
- **`acceptEdits` build-tool gate:** acceptEdits mode requires explicit confirmation before touching `.npmrc`, `.yarnrc*`, `bunfig.toml`, `.bazelrc`, `.pre-commit-config.yaml`, `.devcontainer/` — any file that can execute code at install/build time.
- **grep → edit shortcut:** Single-file grep/egrep/fgrep output now satisfies the read-before-edit requirement, removing the redundant Read step in search-then-edit flows.
- **WSL clipboard fix:** Copy-on-select now routes through PowerShell interop instead of broken OSC 52.
- **Background session teardown:** SIGTERM sent to subprocesses before SIGKILL, allowing cleanup handlers to run.
- **Removed:** `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE` env var (was deprecated in v2.1.154, now a no-op); JetBrains plugin install prompt removed from startup.

Sources: [Claude Code Changelog](https://code.claude.com/docs/en/changelog), [GitHub Releases](https://github.com/anthropics/claude-code/releases)

## Tools & Frameworks

### [NEW] Microsoft Build 2026: Project Polaris, MAI family, Windows as agent platform

Microsoft Build opens today (June 2–3, Fort Mason SF) — its clearest signal yet that it is reducing OpenAI dependency at the foundation model layer.

**Project Polaris** — Microsoft's in-house coding model, now the official future of GitHub Copilot. Mixture-of-experts architecture with per-language sub-modules; beats GPT-4 Turbo on HumanEval and MBPP with notable gains on Rust and Haskell. Replaces GPT-4 Turbo as Copilot default in August 2026; optional three-month fallback to GPT-4 for enterprise teams.

**MAI model family** — MAI-Transcribe-1 (STT), MAI-Voice-1, MAI-Image-2 all available today for commercial use. MAI-Thinking-1, Microsoft's first dedicated reasoning model, unveiled at keynote.

**Copilot Workspace GA** — GitHub's agentic coding environment exits beta: full-repo reasoning, multi-file edits, test-run-iterate loops scoped to a task. Direct competitive surface to Claude Code.

**Windows Agent Framework v1.0 (MIT)** — Cross-environment agent library (local Windows, Windows 365 Cloud PC, Azure Arc edge). Agent Identity ties each agent to a Windows user/service principal; Intune policy enforcement; WDAC extension governs which APIs an agent can call. Routes inference local vs. cloud based on task complexity and connectivity.

**Azure AI Foundry Agents Service GA** — Managed wrapper around the agent framework: auto-scaling, production SLAs, tracing, replay testing, automated red-teaming for agent decision paths.

**Why it matters:** Polaris + MAI mean Microsoft has a full stack play independent of OpenAI. Copilot Workspace GA is the most direct competitive pressure on Claude Code for the "IDE-native agent" position. The Windows Agent Framework architecture (Agent Identity + WDAC governance) is worth studying for anyone building enterprise agents on Windows-managed infrastructure.
