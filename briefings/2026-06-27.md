### [UPDATE] Claude Code June 27 Build: Fullscreen Mouse Control, Voice & Plugin Fixes

**Background:** Claude Code ships near-daily; June 25 (v2.1.191) brought `/rewind`, ~37% CPU reduction, and permanent background-agent stops.

**New:** June 27 build adds `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` env var to suppress fullscreen click/drag/hover events (wheel scroll preserved) — useful for headless CI or terminal multiplexer setups where mouse events interfere. Bug fixes: macOS voice dictation no longer captures silence after a default audio device change in long-running sessions; hook matchers now exact-match hyphenated identifiers like `code-reviewer` or `mcp__brave-search` instead of doing substring matches (was silently misfiring). MCP headersHelper now auto-reconnects on 401/403 errors. Background agents no longer emit "end your response" instructions to the main thread. Remote session startup flow improved with a provisioning checklist.

Sources: [releasebot.io/anthropic/claude-code](https://releasebot.io/updates/anthropic/claude-code), [code.claude.com/docs/en/whats-new](https://code.claude.com/docs/en/whats-new), [GitHub Releases](https://github.com/anthropics/claude-code/releases)

**Why it matters:** The hyphenated hook-matcher fix is worth checking: if you have plugins or hooks with hyphens in identifiers (any MCP server name with a dash, any custom skill), verify they were actually matching before today. The `CLAUDE_CODE_DISABLE_MOUSE_CLICKS` addition suggests remote/CI usage of Claude Code is becoming a first-class target.

## Tools & Frameworks

### [NEW] Agentic Resource Discovery (ARD) Specification — AI Agent Tool Discovery Standard

Eleven companies — Google, Microsoft, Cisco, Databricks, GitHub, GoDaddy, Hugging Face, NVIDIA, Salesforce, ServiceNow, Snowflake — published the Agentic Resource Discovery specification on June 17 (Apache 2.0). ARD answers the runtime question an agent faces when it needs a capability: where does the right tool live, which one should I use, and is it safe to connect?

The spec defines two primitives: (1) a static `ai-catalog.json` manifest hosted at a well-known path on an organization's domain (analogous to `robots.txt` for AI agents), and (2) a registry API that crawls catalogs and returns ranked matches to natural-language queries. The reference implementation is GitHub Copilot's Agent Finder, which indexes ARD-compliant resources without silent installation. The spec builds on the Linux Foundation AI Catalog Working Group data model.

Sources: [Google Developers Blog](https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/), [Microsoft Command Line Blog](https://commandline.microsoft.com/agentic-resource-discovery-specification-ard/), [Technobezz](https://www.technobezz.com/news/google-and-microsoft-lead-11-tech-companies-in-launching-agentic-resource-discovery-specification)

**Why it matters:** ARD is positioned as the discovery layer above MCP — MCP defines how an agent calls a tool, ARD defines how it finds one. For Stack building MCP servers, adding an `ai-catalog.json` to any server you ship is now the path to organic discoverability across the emerging multi-vendor ecosystem.
