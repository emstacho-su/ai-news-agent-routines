### [UPDATE] Claude Code v2.1.163 — enterprise version enforcement, /plugin list, hooks improvements

**Background:** v2.1.162 (June 3) introduced slash commands populating the prompt editor before execution, and OTel integration for enterprise tracing.

**New:** v2.1.163 (June 4, 2026):
- `requiredMinimumVersion` / `requiredMaximumVersion` managed settings — Claude Code refuses to start if its version is outside the allowed range and directs users to an approved version. First enterprise fleet management feature that hard-locks version compliance without external MDM tooling.
- `/plugin list` command with `--enabled` / `--disabled` filters for plugin inventory
- Stop and SubagentStop hooks can now return `hookSpecificOutput.additionalContext` to pass feedback back to Claude and continue the turn without being flagged as a hook error — enables policy hooks that correct rather than abort
- stdio MCP servers now receive `CLAUDE_CODE_SESSION_ID` matching the value hooks and Bash already had, enabling MCP servers to correlate tool calls with the parent session
- Skills: `\$` escape syntax for a literal `$` before a digit in command bodies
- `/btw` "c to copy" shortcut that copies the raw markdown answer to clipboard

Sources: [code.claude.com changelog](https://code.claude.com/docs/en/changelog), [Claude Code releases](https://github.com/anthropics/claude-code/releases), [claudefa.st changelog](https://claudefa.st/blog/guide/changelog)

**Why it matters:** The version enforcement settings close a real enterprise pain point — orgs that need to audit-pin Claude Code versions for compliance can now enforce it at the managed settings layer instead of wrapper scripts.

### [NEW] WWDC 2026 opens June 8 — iOS 27 Extensions confirmed for Claude, ChatGPT, Gemini, Grok

Apple's WWDC keynote is Monday June 8 at 10 AM PT. Beyond what was announced pre-event (Gemini-powered rebuilt Siri via Apple Private Cloud Compute, the Extensions framework for third-party AI), newly confirmed details:
- **All four major AI providers named:** Claude, ChatGPT, Gemini, and Grok are all listed as configurable Extensions options — broader than the originally reported Claude + ChatGPT pairing
- **Implementation:** users install the preferred AI app from the App Store, then configure it as an Extension in Settings > Apple Intelligence & Siri; Apple routes the handoff transparently
- **Distinct voice tiers:** native Siri responses use Apple's voice; third-party model responses (e.g., Claude answering a science question) use a separate configurable voice within the same conversation
- iOS 27, macOS 27, and visionOS 27 all expected; developer betas available immediately post-keynote
- Android 17 Beta 4 is also at near-final stage with stable expected in June — the Gemini Spark 24/7 background agent was in limited US Ultra beta as of late May

Sources: [Tom's Guide WWDC preview](https://www.tomsguide.com/phones/iphones/wwdc-2026), [9to5Mac Extensions report](https://9to5mac.com/2026/05/05/ios-27-will-let-you-choose-between-gemini-claude-and-more-for-ai-features-report/), [Let's Data Science](https://letsdatascience.com/blog/apple-ios-27-extensions-claude-grok-third-party-ai), [MacRumors](https://www.macrumors.com/roundup/wwdc/)

**Why it matters:** An Extensions API at the OS Siri surface means third-party AI SDKs could eventually get system-wide invocation context (current app, system clipboard, accessibility tree) that's currently exclusive to Apple Intelligence. That's a different integration tier from API calls — worth watching how Apple scopes permissions at WWDC.

## Wildcard

### [NEW] Great American AI Act: bipartisan House draft proposes 3-year preemption of state AI model laws

Released June 4, 2026. Led by Reps. Jay Obernolte (R-CA) and Lori Trahan (D-MA) with four bipartisan co-sponsors (Reps. Subramanyam, Franklin, Peters, Houchin). This is a discussion draft — circulated for public feedback before formal introduction, not yet a bill.

Key provisions:
- Preempts state laws "specifically regulating the development" of AI models for 3 years; state laws on AI use and deployment are explicitly preserved
- California laws specifically named as preempted: AB 2013 (training data transparency summaries) and the watermarking portion of SB 942
- Large frontier developers (>$500M annual revenue) must publish safety frameworks, report critical incidents, submit to semi-annual third-party audits
- Codifies the Commerce Department CAISI program, which already conducts pre-deployment security evaluations across five frontier labs
- NSF leads AI literacy programs across K-12 and higher education; creates 8 Centers of AI Excellence
- Requires an AI Workforce Research Hub for labor impact scenario planning

The draft has drawn immediate criticism from Public Citizen, labor unions (AFT), and state attorneys general, who argue it strips consumer and worker protections while deferring to federal oversight frameworks that don't yet exist. Industry response has been more favorable.

Sources: [The Hill](https://thehill.com/policy/technology/5909898-national-ai-framework-draft/), [Axios](https://www.axios.com/2026/06/04/house-draft-bill-regulate-ai), [FedScoop](https://fedscoop.com/bipartisan-great-american-ai-act-draft-proposes-new-federal-ai-governance-framework/), [Roll Call](https://rollcall.com/2026/06/04/bipartisan-ai-draft-proposes-three-year-preemption-of-state-laws/), [Public Citizen](https://www.citizen.org/news/obernolte-trahan-bill-strips-states-authority-to-protect-consumers-workers-and-children/)

**Why it matters:** For anyone building in states with strong AI laws (California, Colorado), a 3-year preemption window would freeze the regulatory environment at the federal floor — which as of June 2026 is mostly voluntary. The timing is deliberate: California's 30 AI bills are mid-crossover, and this draft is a direct counter to Sacramento's pace.
